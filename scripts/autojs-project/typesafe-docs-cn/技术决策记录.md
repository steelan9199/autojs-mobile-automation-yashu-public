## D-01 · `file://` 下的 CORS / ES module 拦截：关不掉，只能绕

### 一句话结论

**没有任何 WebSettings 开关能关掉它**（根因在 Chromium 规范层，不在权限层）；但**六条绕过路线**里，本工程采用 AutoJs6 官方桥 jsBridge（写法是 **`<你的 WebView 变量名>.jsBridge`**，本工程变量名是 `page` ⇒ `page.jsBridge`）。

### 根因（已查证，别再试图"找开关"）

1. `main.js` 里已经开了 `setAllowUniversalAccessFromFileURLs(true)`——它**只能**放开 `XMLHttpRequest` 对 `file://` 的读取。
2. Chromium WebView 官方文档有一条**例外条款**：**"Regardless of this API call, the Fetch API does not allow accessing `content://` and `file://` URLs."**（引自 Android Chromium WebView 文档，见 OWASP MASTG-KNOW-0018）
3. `<script type="module" src="file://...">` 的加载走的是 **Fetch 规范**那条路 → **必然被拦**，与任何开关无关。
4. Android 官方给的替代品是 `WebViewAssetLoader`——那是**改 origin**，不是改开关。

**所以：CORS 是不可关闭项。** 可行的思路只有两类：**①换个 origin**（见方案 D/E）；**②绕开 Fetch**（见方案 A/B/C）。

### 两个反直觉的事实（容易误判，记下来）

1. **被限制的只是"读数据"类 API**（`fetch` / `XMLHttpRequest` 跨 file→http / ES module），**不是所有外链**。
   经典 `<script src="https://...">` / `<link href="https://...">` 在 `file://` 页面下**能正常加载**。
   证据：参考工程 `Vue3 + Vant (SFC)/web/index.html` 直接引 `https://unpkg.com/vue@3/...` 就跑起来了。
   → **但本工程不用这条路**：断网白屏，违反离线铁律。它只说明"技术上可行"。
2. `setAllowUniversalAccessFromFileURLs` **在 Android API 30+ 的 Chromium WebView 上仍生效**（针对 XHR），不是被废弃的无效 API。这也是方案 A 能成立的前提。

### 间接处理方案对照（六条，含未采用的）

| 编号 | 方案 | 原理 | 代码量 | 风险 | 本工程 |
| --- | --- | --- | --- | --- | --- |
| **A** | **XHR 直读绝对路径** | 网页用 `XMLHttpRequest` 读 `file://` 绝对路径（Chromium 明确允许 XHR，设置已开） | ~10 行（`main.js` 只加 1 行注入 `resDir`） | 低。**未真机验证** | **一级回退** |
| **B** | **自搓原生通道** | 网页发信号 → `main.js` 用 `files.read()` 读 → `evaluateJavascript` 回注 | ~25 行 Rhino，与现有 `AJSTATE`/`AJCOPY`/`AJOPEN` 三条同构 | 低。但两条路径要各自自检 | **二级回退** |
| **C** | **★ `page.jsBridge` 官方桥** | 网页 `$autojs.invoke('read-doc', {slug})` → 安卓 `page.jsBridge.handle('read-doc', fn)` 内 `files.read()` 返回 | **~10 行** | 低（官方 API，两个参考工程都印证）。⚠️ 桥挂在 **WebView 变量**上，不是全局 `web`（见下方「宿主的坑」） | **✅ 定案采用** |
| **D** | `JavaAdapter` 挂 `shouldInterceptRequest` | 实现 `WebViewClient.shouldInterceptRequest`，把 `https://docs.local/*` 映射到本地文件 → **文档 origin 变 https，Fetch / ES module 全开** | ~40 行 | **高**：Rhino 重载方法有坑、`WebResourceResponse` 要手工构造、**出错时手机端没有任何报错信息**、调试烧 token 远超收益 | ❌ 不采用 |
| **E** | `WebViewAssetLoader` | Android 官方推荐的"本地 https origin"方案 | — | AutoJs6 **未暴露**该接口，需宿主层改造，做不到 | ❌ 不可用（备查） |
| **F** | 放弃按页读取 | 单文件全量内联，不读文件就不用绕 | 0 行 | 零。但首屏 ~820KB 的老问题原样保留 | **兜底** |

### C 方案的用法（采用）

```js
// 安卓侧：main.js（Rhino / ES5，注意语法门禁）
page.jsBridge.handle('read-doc', function (e, args) {
  return files.read(files.join(files.path('res/docs'), String(args.slug).split('/').join('__') + '.md'));
});
```

```js
// 网页侧：app.js（WebView 里，可用现代语法）
var md = await $autojs.invoke('read-doc', { slug: slug });
```

- 网页侧 SDK 由 AutoJs6 自动注入：`<script src="autojs://sdk/v1.js"></script>`
- 官方 API 形式：`$autojs.invoke(name, args)` → Promise；`$autojs.send(name, ...args)` 单向广播
- 出处：`Vue3 + Vant (SFC)/main.js:22`（`web.jsBridge.handle('fetch', ...)` 读本地 `.vue` 文件——与本工程「按页读 md」是同一个需求）。
  ⚠️ **它那个 `web` 只是 WebView 变量名**（`let web = ui['web']` 恰好遮蔽了同名全局 `web`），**照抄这个名字必失败** —— 见下方「宿主的坑」。

### ⚠️ 互斥关系（必须记住）

**jsBridge 与「自定义 WebViewClient」互斥。**

`jsBridge` 依赖 AutoJs6 自带的 WebViewClient 来接管注入与回调。一旦为了别的目的用 `JavaAdapter` 自定义了 WebViewClient（例：参考工程 `vue-app` 就是这种情况），jsBridge 立刻失效，只能改用古老的 `prompt` 桥。

→ 所以：**方案 C 和方案 D 不能同时要**，别想着"两个都上更保险"。将来若因其他需求必须自定义 WebViewClient，必须同步把 md 读取切到 B。

### 由此确定的两条架构约束

1. **不引 webpack / vite / esbuild 等打包器**。打包器的核心价值是"把 ESM-only 的库编译成浏览器经典脚本"，而我们用的依赖（marked / highlight.js / github-markdown-css）**官方就带 UMD 单文件**，且运行期不产出 ESM → 没有这个需求。引它只会带来 `node_modules`（100MB+）、配置文件、`file://` 下 ESM 产物被拦的不确定性，以及调试配置的 token 成本。**将来若真需要只有 npm 包、无 UMD 版的库，加一条 esbuild 命令即可**（Vite 的内核，一条命令直出经典脚本）。
2. **依赖一律「本地 vendor + 构建期内联 + 运行期零网络」**。CDN 只当下载源（`curl` 抓下来存 `res/vendor/`），**绝不在 `page.html` 里留外链**——断网会白屏。

### 回退链（逐级降级，每级都保留）

```
C（jsBridge）  →  A（XHR 直读）  →  B（自搓原生通道）  →  F（单文件全量内联）
```

### 宿主的坑（2026-09-22 真机实测踩到，**必读**）

**`web` 是 AutoJs6 的真全局**（= `$web`，HTTP 模块），其上**没有** `jsBridge`。

桥挂载的对象是**你自己那个 WebView 变量**：

```js
var page = ui['webview'];   // ← 本工程的 WebView 变量名（id 也叫 page）
page.jsBridge               // ✅ 正确：桥挂在 WebView 对象上
web.jsBridge                // ❌ 错误：web 是 HTTP 模块全局，jsBridge === undefined
```

写错的后果**极具迷惑性**：`TypeError: 无法调用 undefined 的方法 "handle".` 被 catch 吞掉后，
只表现为 `bridge=off`，页面侧 `$autojs.invoke()` **全部静默失败**（不崩、不报错，只是读不到东西）。

→ 纪律：**写 `X.jsBridge` 前先确认 `X` 是你哪个变量**；AutoJS6 预设全局名不许当自己的变量名
（细则见技能库 `references/AI_AutoJS_编码细则.md` §1.7）。

## D-04 · M2 加载通道切换定案（2026-09-22，桌面 + 真机全验）

### 一句话结论

**正文按需从 `res/docs/*.md` 读，`page.html` 瘦成外壳（292 KB）**；
页面级元信息真源搬到 **md frontmatter**，构建期汇总成 `res/data/01-pages.js`；
运行期走 **同步 XHR（绝对路径优先）→ 异步 `page.jsBridge`** 两级通道；
真机上还有第三只手：桥 `list-docs` 运行期重扫目录，**能发现"新丢的 md 还没重跑构建"的新页**。
→ 「加一页 = 丢一个文件」，**构建期**只需重跑一条命令（无新依赖），真机上甚至可以先省掉它。

### 五条定案（别再翻案）

| # | 决策 | 为什么这么做 |
| --- | --- | --- |
| 1 | **每页元信息进 md frontmatter**（`slug/group/order/title/titleEn/url/summary`），`00-index.js` 只剩站点配置 + `plan`（目标清单，界面不读） | 加页不用改 JS。`plan` 保留是给工具核对进度与防漂移用（`check-docs` 会交叉校验），不是界面数据源 |
| 2 | **frontmatter 汇总产物落盘**：`res/data/01-pages.js`（`window.DOC_FM` + 兼容位 `DOC_META.pages`），由 `build-page.cjs` 顺带生成 | 浏览器预览没有桥，扫不了目录 → 必须有一份同步可得的目录；`.js` 产物在构建期被内联进 `page.html`（明文），不受 D-02 的加密影响 |
| 3 | **正文装载四级回退**：内存 → `window.DOC_MD`（仅 `--inline` 形态）→ **同步 XHR**（先 `APPINFO.resUrl` 绝对路径，再相对路径）→ **异步 `$autojs.invoke`** | 抽屉是同步绘制的，**同步命中就零等待**；同步全落空才画骨架、走桥异步补填。桌面预览靠 XHR，真机靠桥，两条都留着才稳 |
| 4 | **`page.html` 两个形态**：默认**外壳**（≤300 KB，46 页齐全时 296 KB）；`--inline` 出 M1 全量形态（~820 KB）当回退 | 46 页齐全后首屏**不再变大**；`--inline` 是通道真出问题时的救命绳，两条形态都有独立校验（`check-docs --expect-inline`）。⚠️ `--inline` 形态**平时不留在 `res/`**（`res/` 里留着它会让默认的 `check-docs` 报错），要用时现跑 |
| 5 | **启动后空闲预取 + 桥重扫目录**（都不阻塞首屏） | ① 之后打开任何一页都是同步命中、无骨架闪烁；② 搜索需要全量正文（懒加载后内存里本来没有全文） |

### 实测得到的新事实（改变了做法，别按旧认知做）

1. **HTML 注释不能嵌套** —— 在注释里逐字写出 `<!--DOCS-->` / `<!--APPINFO-->` 会**提前截断外层注释**，占位符变成出现两次 → `--inline` 形态把整份正文内联两遍（实测踩到：820 KB 变 1.35 MB，且体积异常没人看得出来）。
   → 对策：`build-page.cjs` 现在**断言每个占位符恰好出现 1 次**。
2. **`String.prototype.replace(pat, str)` 会把替换串里的 `$&` / `` $` `` / `$'` 当特殊模式**。往页面注入整份 md（里面 `$` + 反引号的代码片段一大把）时，注入内容会被替换坏（实测踩到：`window.__MD` 直接变 undefined，报错还是"line 4881"这种看不懂的位置）。
   → 对策：注入一律用**函数式替换** `src.replace('</body>', () => probe)`。`selfcheck.cjs` 也一并改了。
3. **主线程同步 XHR 不必害怕**：单页 md 平均 14 KB（最大 71 KB），失败即抛（可判定），实测在 `file://` + `--allow-file-access-from-files` 下稳定可读。

## D-05 · 正文外链路由 + 返回键安全网（2026-09-22，桌面全验，真机待下发）

### 一句话结论

**App 只负责我们翻过的那 46 篇中文页，绝不把自己当浏览器**：正文里点链接 —— 能对上某页 `frontmatter.url` 的
**在 App 内跳那页中文**，其余 `http(s)` **一律交手机默认浏览器**；WebView **不允许自己导航出站**。

### 起因（真机现场，2026-09-22）

「简介」页「后续步骤」里的 `[快速开始](https://docs.typesafe.ai/introduction/quickstart)` —— 锚文本是中文、
target 是英文站 URL。点下去 WebView **自己导航**到线上英文页，**返回键无反应**，人卡在英文页出不来。

根因两条，都不是玄学：
1. `res/app.js` 原本只拦 `data-act` / `data-ext` 这类动作元素，**对正文里的 `<a>` 完全不设防** → 点击走浏览器默认行为 = WebView 导航；
2. 容器返回键只认「抽屉开着 / 不在地图页」两种状态，**管不着 WebView 自己的历史栈**。

### 定案（别再翻案）

| 项 | 定论 |
| --- | --- |
| 判定顺序 | ① 命中我们的页（URL 对得上 `frontmatter.url`）→ App 内跳中文页；② 其余 `http(s)` → `openExt()` 交系统浏览器；③ 相对路径 / `#锚点` / 非 `http(s)` → 不插手，维持默认行为 |
| 反查表 | **运行期**从 `window.DOC_FM` 的 `url` 字段现建（`applyNav` 里灌 `urlSlug`）：不新增产物、不动 md、不改构建 |
| URL 规范化 | 去协议、去 `?query`、去 `#hash`、去尾斜杠、转小写 —— 官方 `.../primitives/` 与 md 里的 `.../primitives` 必须判为同一页 |
| 拦截点 | 网页侧 `res/app.js` 的 `handleLink()`，挂 `touchend` + `click` 两个**捕获阶段**；⛔ **不**用 `setWebViewClient`（红线：会让 jsBridge 整体失效） |
| 拦截窗口 | **不许**按通用动作窗口（原来的 600ms 防抖）跳过链接处理 —— 漏拦一次 = 导航出站 = 用户卡死。只保留一层 **`lastLinkAt` 350ms 去重窗**：同一次点按的 `touchend` 与合成 `click` 会双双进来，第二次**照样吞掉事件**，只是不再重复动作（否则点一下给浏览器开两个标签页） |
| 是否弹窗问用户 | **不弹**。命中中文页无感跳转；未命中沿用既有 toast「已交给浏览器打开」 |
| 「查看英文原文」按钮 | **行为不变**（用户明示要英文 → 直接交浏览器） |
| 返回键 | `back_pressed` 里加一层：抽屉 → **`page.canGoBack()` 则 `page.goBack()`** → 回地图 → 交系统退出。纯防呆层，不依赖它兜外链 |

## D-06 · 搜索结果按「标题相关度」排序（2026-09-22，桌面全验，真机待下发）

### 一句话结论

搜索不再按**目录顺序**排结果，改成**命中位置优先**：
**页标题命中 > `##` 命中 > `###` 命中 > 仅正文命中**；同层再比"标题里命中的关键词个数"，
最后才按目录顺序。每条结果上画出「**命中：〈标题〉**」，**点它 = 跨页打开并滚到那一节**。

### 起因

用户反馈：搜索完，命中标题的那篇文档没有排在最前面。

### 根因（代码级）

旧实现把 `title + titleEn + summary + slug + 整篇正文` 拼成**一个大字符串**做子串匹配（`hay()`）——
**命中位置被彻底丢弃**；而结果收集是遍历 `flat`（目录顺序）。
于是"页名就叫《State（状态）》的页"和"正文里顺嘴提了一句 state 的页"混在一起，排序与相关度完全无关。

### 定案（别再翻案）

| 项 | 定案 |
| --- | --- |
| 排序键 | ① 层级 `1 页标题 / 2 ##/ 3 ###/ 4 仅正文` → ② 该层命中的关键词数（降序）→ ③ 目录顺序 |
| 命中集口径 | **一个字没改**：仍要求**所有**关键词都在页内出现（AND）。本次**只改顺序、不改结果数量** —— 零回归风险 |
| 标题索引 | `titleIndex(slug)`：页标题的中文名与英文名**各算一条**（都属 level 1）+ `scanMd().toc` 的 `##`/`###`；`id` 直接复用 `decorate()` 补的 `sec-N`。懒建 + 按 slug 缓存 |
| 顺序一致性 | 结果列表与抽屉「上一个/下一个」**共用 `searchOrder()`** —— 两处顺序必须一致 |
| 命中行 | 结果条目多一行「命中：〈标题〉」，该行**同时带 `data-id` + `data-toc`** |
| 点击语义 | `data-id` + `data-toc` 同带 = 跨页打开并跳那一节；只带 `data-toc` = 当前页内跳（原行为不变） |
| 分组小标题 | 排序不再按分组聚拢 → 分组名只在**换组**时插一次（每条都插会变成一串重复分组名） |
| 中英标题 | 拆成两条索引项而不是拼成一条 —— 拼起来会让命中行显示成「命中：State（状态） State」 |

### 时序陷阱（本次唯一容易写错的地方）

**跳小节必须发生在 `restorePos()` 之后**，原因有两层：

1. 正文走异步通道时，锚点 `sec-N` 要等正文**补填完**才存在 → 不能立刻跳，必须等；
2. 补填完还会 `restorePos()` 恢复上次阅读位置 —— **它会把刚做的跳转冲掉**。

解法：`doJump()` 用**轮询**（100ms × 30 ≈ 3s 上限）等锚点出现。`tick` 是宏任务，一定排在
"补填 + `restorePos`"那两行之后，两个坑一起绕过；等不到就安静放弃（不报错、不打断阅读）。
`openSheet()` 开头**取走即清空** `pendingToc`，避免用户在正文补填完成前关闭抽屉/翻页导致残留。
