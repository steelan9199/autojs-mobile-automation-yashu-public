# AI视频概念地图 · AutoJS6 工程

把《从一句话到一部片：AI视频人要懂的影视语言全地图》做成一个可以随身翻的离线 App。
**零联网、零权限、零申请**——47 个概念全在工程里，装上就能用。

---

## 一、目录结构

```
ai-video-map/
├─ project.json          # 打包配置：应用名 / 包名 / 版本号（打包前改版本号）
├─ main.js               # 入口：合成页面 + 全屏 WebView（第 1 个字符必须是 'ui';）
├─ res/                  # 页面与内容
│   ├─ index.html        # 页面骨架（可以单独用浏览器打开预览）
│   ├─ style.css         # 深色电影感主题 —— 改观感只改这里
│   ├─ app.js            # 交互逻辑（地图 / 列表 / 收藏 / 搜索 / 抽屉）—— 改交互只改这里
│   ├─ concepts.js       # ★ 全部 47 条内容数据 —— 改内容只改这里
│   └─ page.html         # 自动生成：四件套预合成的单文件页面（打包形态读它，别手改）
├─ tools/build-page.cjs  # 生成 page.html 的脚本（改完 res/ 后跑一次）
└─ README.md
```

**改内容** → `res/concepts.js` ｜ **改外观** → `res/style.css` ｜ **改交互** → `res/app.js`
三者互不牵连，改完都不用动 `main.js`。

## 四、打包成 APK（在手机上做）

1. **先在电脑上跑一次** `node tools/build-page.cjs` —— 生成/刷新 `res/page.html`
   （打包形态靠它出内容，详见第五节第 5 条；忘了跑 = APK 里是旧页面）。
2. 把整个 `ai-video-map` 目录放到 AutoJs6 能看到的位置（默认 `/sdcard/脚本/`）。
3. 打开 AutoJs6 → 进入该工程 → 点工具栏的**打包图标**
   （部分版本是长按项目卡片唤出「打包」菜单）。
4. 打包配置页会自动读 `project.json`，确认这几项：
   - 应用名：**AI视频概念地图**
   - 包名：**com.musk.aivideomap**
   - 版本号：`1.0.0` / `1`
   - 图标：**在打包页单独选**，工程里不用放图标文件，选你做好的图就行
   - 权限：本 App 不需要任何权限，可全部不勾
5. 点**开始打包**，完成后按提示安装。
6. 产物同时落在工程目录的 `build/` 下，那个 `.apk` 就可以发给别人。
7. 以后改了 `res/` 里的内容，**必须重新打包** APK 才会生效（改版本号后再打，避免系统拒绝覆盖安装）。

> **发给别人之前提醒一句**：对方安装时会弹「未知来源应用」，需要在系统设置里允许一次。
> 提前说一声，免得对方以为装了个不正经的东西。

## 五、四个"别随手改"的写法（都踩过坑）

### 1. `main.js` 第 1 个字符必须是 `'ui';`
AutoJs6 只认文件第一个字符的 UI 模式指令。注释、空行、BOM 挡在前面都会让它**静默失效**，
报出来的错却是 `activity is not defined` 之类，很容易误判成 API 用法问题。

### 2. 页面由 `main.js` 在运行期合成，而不是让 html 自己按相对路径加载 css/js
**这是本项目最贵的一个坑。** 页面用 `<script src="app.js">` 这种相对路径加载子资源时，
WebView 层会复用旧副本：主文档 `index.html` 是新的，`app.js` 却还是老的 ——
表现出来是**页面渲染完全正常，但所有点击、切换、收藏全部失效**，
而且改多少遍代码、重启多少次都不生效。

所以 `main.js` 会把 `index.html + style.css + concepts.js + app.js`
合成一份"自带全部内容"的 HTML，写到 App 私有目录再打开（`buildBundle()`）。
没有子资源请求，这个坑从根上没有了。

> 代价：以后改 `res/` 里的文件，APK 需要**重新打包**才生效——
> 但正常流程本来就要重新打包，所以不影响使用。
> `res/index.html` 仍保留 `<link>` / `<script src>` 写法，方便你直接用浏览器打开预览。

### 3. XML 的 `<webview>` 不写 `url` 属性
写了 `url`，WebView 在布局膨胀那一刻就开始加载页面，而
`setJavaScriptEnabled` / `setDomStorageEnabled` / 缓存策略只能在那之后执行
—— 首次加载等于"裸奔"。正确顺序是：
**声明空 WebView → 配置 → 最后 `loadUrl`**。

另外没用 `web.newInjectableWebView()`：它更"原生"，但**没有 `.events`**，
拿不到页面的 `console_message`，硬件返回键就失去了页面状态。

### 与网页的通信（只有两条，都不依赖自定义 bridge）

- **网页 → 安卓**：网页调 `console.log("AJCOPY:" + encodeURIComponent(文本))` → 容器写系统剪贴板；
  另外用 `AJSTATE:{sheet,tab}` 上报界面状态，给硬件返回键判断用。
- **安卓 → 网页**：`page.evaluateJavascript(js, null)`（封装成 `evalInPage()`）；
  启动信息（工程路径等）用 `<!--APPINFO-->` 占位符注入成 `window.APPINFO`。

复制特意走容器而不是 WebView 自己 `execCommand('copy')`——后者在部分机型/权限下会静默失效。

### 4. 安卓 → 网页 一律走 `evaluateJavascript`，不用 `loadUrl('javascript:...')`

**症状**：打开某个概念详情，按手机返回键 —— 整个页面消失，变成全黑。

**原因**：`loadUrl('javascript:...')` 有个反直觉的行为——**脚本的求值结果若是一个字符串，
WebView 会把这个字符串当成新页面去加载**。当时的 `AJClose()` 返回 `'closed'`，
于是容器让它关抽屉，结果整个页面被替换成一页只写着 "closed" 的空白文档；
WebView 底色是 `#0B0C10`，看上去就是全黑、页面没了。

**修法（两层，都别退回去）**：

- `main.js` 统一用 `evalInPage()` → `page.evaluateJavascript(js, null)`，它只执行、不导航；
  兜底分支写成 `loadUrl('javascript:void(' + js + ');')`，用 `void` 保证求值结果一定是
  `undefined`，这样就算退回 `loadUrl` 也不可能再触发页面替换。
- `res/app.js` 里的 `window.AJClose` / `window.AJHome` **一律不返回值**。
  别为了"回传执行结果"给它们加 `return 'closed'` 之类——那正是这个 bug 的源头。

> 同一类风险还有：任何 `return` 字符串的脚本、任何把结果拼进 `javascript:` URL 的写法。
> 判断标准一句话：**这个脚本求值出来是不是字符串？是就别用 `loadUrl`。**

### 返回键行为（三条分支，已实机验证）

| 当前状态 | 按返回键 |
| --- | --- |
| 详情抽屉开着 | 关抽屉，停在原页面 |
| 在「概念」或「收藏」页 | 回「地图」页 |
| 已在地图页、无抽屉 | 交给系统退出 App（正常退到 AutoJs6 界面） |

分支由页面通过 `console.log('AJSTATE:{sheet,tab}')` 上报的状态决定，容器只读不猜。

### 5. 运行期只读 `.html/.css`，绝不读工程里的 `.js`（打包必踩）

**AutoJs6 打包 APK 时会把工程内所有 `.js` 文件加密**（APK 里 `assets/project/res/concepts.js`
头部是 `77 01 17 7F ...` 的密文），只有 `.html` / `.css` 这类资源是明文原样打包。

所以运行期 `files.read('res/concepts.js')` 在**打包形态**下读到的是密文，
内联进 `<script>` 直接语法错误 →
**页面只剩 HTML 骨架那几行字**（标题、搜索框、底部 Tab 都在，地图/列表/47 条内容全空），
而中继运行（工程在 `/sdcard` 是明文）一切正常 —— 极易误判成前端 bug。

现在两条路并存：

- **优先**读 `res/page.html` —— PC 侧预合成的单文件页面（`.html`，明文资源，打包形态一定读得到）；
- 没有 `page.html` 时才退回运行期合成（中继形态走这条，永远最新）。

**但有两条看着能解、其实没用的路，别再花时间（2026-09-20 最小工程对照实验锤死）**：

- ❌ `project.json` 的 `"assets": ["res/app.js", "res/concepts.js"]`
  —— 官方对该字段的注释是"保留字段，暂时没有作用"。实测重打包后那两个 js 依旧是密文（`77 01 17 7F`），而且全包**没有生成任何明文副本**。
- ❌ `project.json` 的 `"encryptLevel": 0`（Auto.js **Pro** 的"0-不加密"字段）
  —— 实测无效，而且 AutoJs6 打包时会**直接丢弃这个字段**（写回的 `project.json` 里没有它），说明它压根不认识这个键。它对工程内 `.js` 是无条件 AES 加密（密文前写 `EncryptedScriptFileHeader`，密钥取 `MD5(包名+版本名+主脚本名)`，所以**每次打包密文都不一样，不能跨版本复用**）。
- 🔍 想自己验证：解密文只要看**头部字节**（密文 `77 01 17 7F` / 明文 HTML `3C 21 44 4F 43 54 59 50 45`），或对比**条目大小**：密文比本地明文固定多 16~17 字节，而 `index.html` 大小分毫不差。

> **判决依据**：上面两条不是靠推理，是**对照实验**打出来的结论。
> 实验台在 `../min-encrypt-test/`（同级目录，保留着）：把 `data.js` 写进 `assets` 数组、
> `keep.js` 不写，两者内容同构；同一次打包还带 `"encryptLevel": 0`。
> 结果**这两个 js 的头部字节一模一样**（`77 01 17 7F 12 12 00 00`）——进了白名单的和没进的没区别。
> 探针会把每个文件的明文/密文直接显示在 App 弹窗上，以后有同类疑问直接重跑它。

> 现状（2026-09-20）：`page.html` 方案已在**真机 APK 形态**验证通过 —— 打包安装后地图 / 47 条概念 / 收藏全部正常。

**改完 `res/` 里任何文件，打包前必须跑一次：**

```bash
node tools/build-page.cjs
```

忘了跑不会崩，但 APK 里会是旧页面（中继运行看不出来，只有打包形态才现形）。

## 六、打包后出问题，按这个顺序查

**症状：打开 App 只剩几行字（标题/搜索框/底部 Tab 在，内容全空）**

1. 先看 `res/page.html` 是不是最新的：跑一遍 `node tools/build-page.cjs`；
   没生成过就生成，然后**重新打包**（这是唯一必须重打的原因）。
2. 还想确认病根：解开 APK 看 `assets/project/res/concepts.js` 的头部
   —— `77 01 17 7F` 开头 = 被加密（正常现象），说明它**只能当脚本跑，不能当数据读**；
   `.html/.css` 则应是明文。据此就能判断页面是不是踩了"运行期读 .js"的坑。
3. 日志：把 `project.json` 的 `"hideLogs": true` 改成 `false` 再打包一次，
   能看到 AutoJs6 的日志浮窗，错误写在上面。
4. 若日志显示读不到 `res/`：说明打包时没带上 `res/` 目录 —— 告诉我，改成
   "把页面整体内联进 main.js"的形态即可，功能不受影响。
5. 若日志正常但仍空白：多半是 `files.cwd()` 在打包形态下没指向工程目录。
   `pickResDir()` 已预置三条候选路径；把日志里的实际路径发我，我补一条即可。
