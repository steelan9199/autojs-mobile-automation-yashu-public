# qiu-draw-path · 画曲线/路径

## 使用场景

- 球球大作战画板上画任意形状：轮廓线、头发分块、墨镜边框、嘴型等；
- 直线、折线、曲线都能画——曲线靠多个中间点逼近，点越密越平滑；
- 与"点颜色块"、"选笔粗"模板配合，先选好颜色和粗细再调用本模板。

## 坐标权威源（必读）

**本模板涉及的一切界面坐标，一律以手机任务模板 `qiu-calib` 的存储为准**，不要使用本文或脚本注释里的历史值、估算值。
本模板自身只吃 `points`（作画轨迹），不内置按钮坐标；但**调用前选色、选笔粗、切工具**那些动作的坐标，同样必须走 `qiu-calib`。

| 用途 | 命令 / 代码 |
|---|---|
| 读回全部坐标（PC） | `node scripts/run-task.js qiu-calib-read --args '{"op":"list"}'` |
| 按按钮名直点（PC） | `node scripts/run-task.js tap-calibrated --args '{"name":"粗笔"}'` |
| 脚本内取单个坐标 | `storages.create("qiu-calib").get("粗笔")` → `{x,y,rot,ts}` |
| 重新标定 | `node scripts/run-task.js qiu-calib --args '{}' --wait 0` |

- 存储位置：AutoJS `storages` 命名空间 `qiu-calib`，键=按钮中文名，值 `{x,y,rot,ts}`；
- 坐标与屏幕方向绑定（当前全部为 `landscape`）——**标定与使用都必须在横屏下**；
- 标定/更新流程详见 `scripts/tasks/qiu-calib/TASK.md`。

## 参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `duration` | number | 是 | 整条手势时长（毫秒）。越快越抖、越慢越平滑；短线 200~500ms，长曲线 1000~2000ms |
| `points` | array | 是 | `[[x1,y1],[x2,y2],...]`，至少 2 个点。坐标是屏幕绝对像素 |

## 返回

- 成功：`{ok:1, duration, pointCount}`；
- 失败：`{ok:0, err}`——参数缺失/非法时直接返回。

## 怎么规划坐标点（基础）

1. 先跑 `get-screen-size` 拿屏幕宽高；
2. 截图量画板圆形的**圆心 (cx, cy)** 和**半径 r**——画板外的轨迹不显示；
3. 把要画的形状拆成多条路径，每条路径是一组 `[x,y]`；
4. 曲线用参数方程在数学曲线上**密集采样**，而不是手画几个顶点。

## 球球画板实测坐标系（2026-09-16 真机实测）

| 项 | 值 |
|---|---|
| 屏幕分辨率 | 3200 × 1440（横屏） |
| 画板圆心 (cx, cy) | 约 **(1600, 720)** |
| 画板半径 r | 约 **550**（圆边到圆心距离） |
| 安全作画区 | 距圆心 ≤ 500 的范围内，避免被圆边裁切 |

后续画头像/图案都以这个为基准；不同手机/分辨率下重新跑 `get-screen-size` + 截图量圆心。

## ⭐ 怎么画出平滑曲线（核心经验，实测验证）

**gesture 内部是相邻点之间直线连接**——要看起来像曲线，必须用足够密的点把折线"伪装"成曲线。实测对比：

| 点数 | 相邻点间距 | 时长 | 效果 |
|---|---|---|---|
| 7 | ~150px | 1.5s | **折线感明显**，一眼看出棱角 |
| 21 | ~55px | 2.0s | **平滑 S 曲线**，肉眼看不出折角 |

**经验公式**：
- **相邻点间距 ≤ 40px** 才看不到折角；圆/弧建议 ≤30px；
- **时长 ≥ 1.5 秒**才平滑；短线可短，曲线必须给够时间；
- **点数参考**：半圆弧 ≈ 20~25 点，整圆 ≈ 40~48 点（每 8~9° 一点），S 形 ≈ 20~30 点。

### 常用曲线采样公式（PC 端算好 points 数组再下发）

**圆 / 圆弧**（圆心 cx,cy，半径 r，起止角 a1~a2，单位度）：
```
每步 Δθ=8°：
points = [[cx + r*cos(θ), cy + r*sin(θ)] for θ in range(a1, a2+Δθ, Δθ)]
```
整圆：a1=0, a2=360，约 45 个点，时长 2500ms。

**正弦波**（振幅 A，周期 W，从 x0 到 x1）：
```
y = cy + A * sin((x - x0) / W * 2π)
每 40~50px 取一个 x
```

**直线**：2 个点即可，时长 300~500ms。

### 多段曲线拼接

一条连续路径 = 一次 gesture。断开的形状（如两个分开的眼睛）要分多次调用本模板，每次之间可先切颜色/笔粗。

## 示例

```bash
# 短线（直线）
node scripts/run-task.js qiu-draw-path --args '{"duration":400,"points":[[1400,720],[1800,720]]}'

# 平滑 S 正弦波（21点，实测平滑）
node scripts/run-task.js qiu-draw-path --args '{"duration":2000,"points":[[1050,720],[1105,760],[1160,796],[1215,825],[1270,844],[1325,850],[1380,844],[1435,825],[1490,796],[1545,760],[1600,720],[1655,680],[1710,644],[1765,615],[1820,596],[1875,590],[1930,596],[1985,615],[2040,644],[2095,680],[2150,720]]}'

# 整圆（圆心1600,720 半径400，每8°一个点）
# PC 端用 Python/JS 算好 45 个点再下发：
# for θ in 0..360 step 8: [1600+400*cos(θ°), 720+400*sin(θ°)]
node scripts/run-task.js qiu-draw-path --args '{"duration":2500,"points":[...45个点...]}'
```

## 什么时候不该用

- 只是点一下按钮——用 `tap-point` 或 `pc-ocr` 找坐标后点；
- 翻页/滑动列表——用 `swipe`；
- 需要填色块——本模板只画线，填色靠多道平行轨迹堆叠。

## 红线提醒

- 本模板**不会**自动选颜色/笔粗——调用前确认当前选中的颜色和粗细就是想要的；
- 手势时长太短会画成点、太快会抖；**曲线 ≥1500ms、点间距 ≤40px** 才平滑（见上节实测）；
- 一次手势最多画一条连续路径，断开的形状要分多次调用。
