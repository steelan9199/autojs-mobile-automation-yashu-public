# ad-claim-loop · 看广告领奖循环

把「点广告 → 看广告 → 领奖 → 回游戏」这条人工重复链路一次性跑满 N 轮，中途不打扰，
任一步校验不通过就**立即停止**并回报卡在哪一轮哪一步。

**分类**：长任务类（坐标手势 + 流程控制合体）。纯坐标驱动，不查控件树；
一次下发在手机端内部循环，PC 侧只收一条终态回执。

## 使用场景

- 游戏内每日「看广告领奖励」需要重复几十次，人工点太累。
- 规律是「横屏按钮 A → 变竖屏播广告 → 竖屏按钮 B → 变回横屏」，且步骤数固定。
- 需要无人值守跑十几分钟，且失败时要知道卡点以便人工接手。

## 什么时候不该用

- 只有一轮 → 直接用 `tap-point` + `wait` 拼两步即可，不必上本模板。
- 不知道按钮坐标 → 先用 `ocr`（`query` 关键词 + `detail:true`）或 `inspect-control-by-text` 拿坐标，
  再回来填 `gameX/gameY/adX/adY`。
- 需要点击后再读屏判断该点哪个按钮（而非固定坐标）→ 本模板是纯坐标驱动，改用 `ocr` / `tap-text` 组合。
- 只想点一个坐标（不循环）→ 用 `tap-point`。

## 参数细节与坑

| 参数 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `gameX` / `gameY` | ✅ | — | **横屏坐标系**下「广告获取」按钮坐标 |
| `adX` / `adY` | ✅ | — | **竖屏坐标系**下「领取成功」按钮坐标 |
| `rounds` | | 25 | 轮数，夹取到 1~200 |
| `adSec` | | 31 | **从点击广告按钮起算**的总等待秒数，夹取到 1~180 |
| `probeSec` | | 5 | 点广告按钮后查方向的间隔秒数，夹取到 1~60 |
| `settleMs` | | 20000 | 「领取成功」后等回横屏的超时（毫秒），夹取到 1000~30000 |
| `settleStepMs` | | 1000 | 方向轮询间隔（毫秒），夹取到 250~5000 |

### 拉起广告的重试规则

点击广告按钮后**不靠一次判定**，而是：

1. 点击 → 等 `probeSec`（默认 5）秒 → 查方向；
2. 仍横屏 → **再点一次** → 再等 `probeSec` 秒 → 再查方向；
3. 竖屏 → 广告已正常进入，继续走流程；
4. 第 2 次后**仍是横屏** → 判定「广告未拉起」→ **立即停止任务**（`stage: ad-not-launched`）。

即最多重试 1 次。广告 SDK 偶发无填充/首次点击不响应，补一次点击能救回大部分情况；
再失败说明确实拉不起来，继续硬点只会空跑，故停止。

⚠️ **`settleMs` 已不再用于判定广告拉起**（改由上面的 `probeSec` 两连点判定），
现仅用于「点击领取成功后等回横屏」。

⚠️ **两套坐标系不可混用**：广告 SDK 常强制竖屏，此时屏幕物理分辨率与横屏时**互换**
（实测：游戏横屏 3200×1440，广告竖屏 1440×3200）。`gameX/gameY` 与 `adX/adY`
必须分别取自各自方向下的实测坐标，拿横屏的坐标当竖屏用会点到完全无关的位置。

⚠️ **`adSec` 的计时起点是「点击广告按钮的那一刻」**，不是「广告画面出现的那一刻」——
广告 SDK 拉起 + 加载通常要几秒，这段时间本身已在倒计时里，脚本只补剩余差额。
所以 `adSec` 要设成「加载耗时 + 视频时长 + 2~3 秒余量」；实测 31 秒视频建议设 **35**。

⚠️ **`settleMs` 别设太小**：点击广告按钮后屏幕要过几秒才被广告 SDK 转成竖屏（加载期间仍是横屏）。
该判定现已改用 `probeSec` 两连点逻辑（见上），不再受 `settleMs` 影响。

⚠️ **`adSec` 仍是固定盲等**：广告实际总时长 > `adSec` 时，`领取成功` 尚未出现 → 点击落空 →
紧随其后的「等回横屏」校验失败 → 脚本按设计停止。**这是预期行为，不是 bug**；把 `adSec` 调大即可。

💡 长任务会先调 `device.keepScreenOn(30min)` 保屏幕常亮，避免中途熄屏导致点击失效。

## 错误处理与兜底

**设计取向：任一步失败立即停止，不重试、不跳过**（保证不会静默空跑、不会漏领还继续）。

失败回执带三个定位字段，直接告诉 AI 卡在哪、成功了几轮：

```json
{ "ok": 0, "err": "第 7 轮失败[wait-back-landscape]：点击「领取成功」后 6000ms 内未回到横屏（广告可能还没播完）",
  "failedRound": 7, "stage": "wait-back-landscape", "done": 6 }
```

`stage` 取值与含义：

| stage | 含义 | 常见原因 / 处置 |
| --- | --- | --- |
| `check-landscape` | 轮次开始时不是横屏 | 游戏页未就绪 / 被弹窗盖住 / 已离开游戏 |
| `ad-not-launched` | 连点 2 次广告按钮、各等 `probeSec` 秒后仍横屏 | 广告无填充 / 按钮坐标偏了 / 点击被拦截 |
| `wait-back-landscape` | 点了领奖按钮但没回横屏 | `adSec` 太短广告没播完 / 领奖坐标偏了 |

停止后屏幕会**停在失败现场**，AI 可立即下发 `screenshot` 看当时画面，据此修正坐标或 `adSec`。

## 示例调用

```bash
# 实测场景：游戏横屏按钮 (904,1272)、广告竖屏按钮 (1190,196)，跑 25 轮
node scripts/run-task.js ad-claim-loop --args '{"gameX":904,"gameY":1272,"adX":1190,"adY":196,"rounds":25,"adSec":35}'
```

长任务，必须 `--wait 0` 立返单号，再轮询：

```bash
node scripts/run-task.js ad-claim-loop --args '{...}' --wait 0      # 立返 taskId
node scripts/run-task.js --status <taskId>                          # 查进度（含 __reportProgress）
node scripts/run-task.js --stop <taskId>                            # 卡死时强杀
```

单轮耗时 ≈ `adSec + 1~2` 秒（加载耗时已含在 adSec 内）；`adSec=35` 时 25 轮约 15 分钟。

## 红线提醒

- 本模板只做**点击 + 等待**，不涉及支付、转账、删除、授权等不可逆操作。
- ⛔ 先与用户确认再跑——循环 25 轮属于批量行为。
- ⛔ 不要用本模板去点「关闭/卸载/退出登录」类按钮；坐标一旦偏了就批量误触。
