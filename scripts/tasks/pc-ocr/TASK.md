# pc-ocr · 调用电脑本地 OCR 识别手机屏幕

## 使用场景

- 球球大作战等**不支持无障碍**的游戏界面，手机内置 `ocr.detect` 或文字定位不准时；
- 需要把屏幕文字连同**点击坐标**一起拿回来（本模板返回的 items 带中心坐标，可直接 `click(x,y)`）；
- 任何希望用电脑端 PP-OCRv6 引擎识别手机画面的场景。

## 前置条件（缺一不可）

1. **电脑端 RapidOCR 服务已启动**，且监听 `0.0.0.0:8765`（本机 `start ocr --host 0.0.0.0`）；
2. **手机与电脑同一局域网**，手机能访问电脑 IP；
3. 手机常驻客户端 `autojs-task-phone-client.js` 正在运行（提供 `relay-config.json` 里的电脑 IP）；
4. 截图权限已授权（首次会自动点掉"立即开始"弹框）。

## 参数细节

- `query`（选填）：只返回 `text` 包含该字符串的 item。用于"找按钮"——例如 `{"query":"清空"}` 直接拿到"清空"按钮的中心坐标；
- `minScore`（选填）：默认 0.85，调低（如 0.6）可召回低置信度文字，调高（如 0.9）去噪。

## 返回结构

```json
{
  "ok": 1,
  "full_text": "第一行\n第二行",
  "items": [{"text":"清空","x":460,"y":1560,"score":0.97}],
  "elapse": 0.88
}
```

- `items[].x / y` 是文本块**四角点平均中心**，可直接 `click(x,y)`；
- 不传 `query` 时返回全部命中项（可能较长，仅用于通读屏幕）；传 `query` 时只回命中项，省 token。

## 错误处理与兜底

- `err` 里会带 HTTP 状态码或连接错误——网络失败 = 电脑 OCR 没启动 / 没绑 0.0.0.0 / 防火墙未放行 8765；
- 命中 0 项时 `ok:1` 但 `items:[]`，不是错误——可能是 `min_score` 太高或文字确实不在屏幕上；
- 超时建议 60 秒（CPU 推理单张 0.5~2.5 秒，但网络+上传另计）。

## 什么时候不该用

- 界面**支持无障碍**时，优先用 `inspect-control-by-text` / `tap-text`（更快、更省、不依赖电脑 OCR 服务）；
- 只想读屏幕文字不要坐标时，`ocr` 模板（手机内置）也可，但精度不如本模板；
- 需要识别图片文件（不是当前屏幕）时，直接在 PC 端 curl 本地 OCR 服务，不用走手机。

## 示例调用

```bash
# 读全屏文字
node scripts/run-task.js pc-ocr --args '{}'

# 找"清空"按钮的坐标
node scripts/run-task.js pc-ocr --args '{"query":"清空"}'
# 返回 {"ok":1,"items":[{"text":"清空","x":460,"y":1560,...}],...}
```

## 红线提醒

- 本模板只截屏上传识别，不点击任何东西；要点击请配合 `tap-point`。
- 电脑 OCR 服务无鉴权、绑 0.0.0.0 时全局域网可访问，用完建议停掉或改回 127.0.0.1。
