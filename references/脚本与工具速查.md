# 脚本与工具速查（PC 端 Node 脚本）

> 本文件从 SKILL.md 下沉而来，**按需查阅**，不必通读。
> 什么时候读这里：要传文件、部署/运行/删除工程、更新手机客户端、查任务单、取局域网 IP 时。

## 一、日常高频四件

### `scripts/run-task.js` — 下发模板或脚本（主力入口）

把模板名/脚本文件 + 参数 POST 到中继 `/run`（异步任务单），默认轮询最多 30 秒等回执并打印。长任务加 `--wait 0` 立即返回 taskId。

```bash
cd <skill_dir> && node scripts/run-task.js open-app --args '{"name":"MT管理器"}'
# 等价：--name open-app / --path tasks/open-app/open-app.js
```

任务单控制：

- `--status <taskId>` 查状态/进度/结果，**跨会话可查**；
- `--stop <taskId>` 强杀——**只对未终态的任务单有效**。对"建好即回执"的 UI/常驻类脚本无效：回执一到任务单即终态，`--stop` 返回 `alreadyFinished` 而手机端引擎仍常驻（悬浮窗还在）。停残留引擎走 `list-running-scripts` → 拿实时引擎 id → `stop-script-by-id`；
- `--list [数量]` 列最近任务单；
- 不带参数运行打印完整用法。

回执要点：

- `status` 是**任务单生命周期状态**（submitted/running/success/failed/stopped），`success` 只代表跑完并拿到回执；**业务成败要看 `result` 里的 `ok`**；
- 启动期失败（脚本 404）时 `status` 仍为 `success` 而 `result.ok=0`、`result.phase="client"`；
- 中继侧提交超时熔断则 `result.phase="relay"`；
- 30 秒超时**不是失败**，任务仍在手机跑，用 `--status` 继续查；提交后 60 秒未被接单，中继熔断为 failed。

### `scripts/scan-tasks.js` — 扫模板清单（省 token 的两级读取）

- `node scripts/scan-tasks.js` → 默认输出每行 `name — description`（给 AI 规划用，最省 token；比 JSON 每次省约 1100 字符）；
- `node scripts/scan-tasks.js --json` → 紧凑 JSON 数组（给脚本消费）；
- `node scripts/scan-tasks.js --human` → 输出「共 N 个 + 可读清单」（给用户朗读用）；
- 中继 `GET /templates` 复用同一份扫描逻辑，外部程序取数用它。

成功任务的历史实测耗时会自动附在描述末尾 `[平均 X 秒]`（截尾平均：去掉 1/3 最大与 1/3 最小后取均值，滚动保留最近 10 次）。

### `scripts/pc-to-phone.js` — 电脑传文件到手机（高频刚需）

```bash
node scripts/pc-to-phone.js <本地文件> [--target-dir <手机目录>] [--target-name <手机文件名>] [--keep]
```

- 路径一律以技能目录为基准写**相对路径**；`<本地文件>` 是**数据参数**（要传的文件），别和 node 脚本路径搞混；
- `--target-dir` 缺省经 `/health` 动态推导为 `scripts-from-computer/files/`；显式指定则指哪打哪；
- `--keep` 保留电脑中转副本（默认回执后清理）；
- 反方向（手机→电脑）用模板 `download-file`。

### `scripts/self-test.js` — 一键回归自测

健康检查、参数/剪贴板往返、截图压缩、delete-path 护栏、工程全生命周期、任务单列表一次跑完，输出 ✅/❌ 汇总与退出码。**改中继/客户端/模板后跑它自证未改坏。**

## 二、工程与文件

### `scripts/deploy-project.js` — 部署多文件工程到手机并运行

复杂工程（多模块 / 带图片音频资源，单文件模板装不下）用它而非单文件模板。

```bash
node scripts/deploy-project.js <工程目录> [--name <工程名>] [--main <入口.js>] [--run|--no-run] [--args '<json>'] [--keep] [--dry-run] [--zip|--no-zip] [--keep-zip]
```

**传输形态默认自动判定（SKILL.md 硬约束 12）**：含子目录结构 或 文件数 ≥5 ⇒ 打成一个 zip、只走一次传输、手机端解压；只有「<5 个且全部平铺」才逐文件。**别手动加 `--zip`**——默认已经是对的；`--zip` / `--no-zip` 只用于强制覆盖（后者仅调试场景）。`--dry-run` 会打印判定理由且不连手机。工程例必命中打包（工程必有子目录），所以正常使用就是一条命令。

### `scripts/run-project.js` — 跑已部署工程（不重传文件）

换参数反复跑已部署工程时用。

```bash
node scripts/run-project.js <工程名> [--main <入口.js>] [--args '<json>'] [--wait 秒]
```

与 run-task.js 同一套任务单模型：默认等 30 秒回执，`--wait 0` 立返 taskId。

### `scripts/delete-project.js` — 删除手机上已部署的工程

```bash
node scripts/delete-project.js demo            # 删 scripts-from-computer/project/demo
node scripts/delete-project.js --path <任意 sdcard 存储内路径>
```

手机端带安全护栏：传入路径先规范化（解析符号链接与 `..`），只放行 sdcard 存储内路径。

## 三、维护与连接

### `scripts/autojs-relay-server.js` — PC 端中继服务

HTTP + WebSocket。架构细节见 `scripts/relay/ARCHITECTURE.md`。**启动必须用 Bash 工具受管后台（`run_in_background:true`），严禁命令末尾 `&`**：

```bash
cd <skill_dir> && node scripts/autojs-relay-server.js
```

验证活着：`curl -s http://localhost:9421/health` → `"status":"ok"` 即活、`"phone":"connected"` 表示手机也连上。
**完整的启动/验证/判别 SOP（含「手机超时连不上」与客户端假死）见 `中继存活SOP.md`。**

### `scripts/autojs-task-phone-client.js` — 手机端常驻客户端

**严格 ES5，变量一律 var**。用户复制到手机 AutoJs6 运行。负责保活、断线重连、按名下载脚本执行、回传结果。

### `scripts/update-phone-client.js` — 一键更新并重启手机客户端

```bash
node scripts/update-phone-client.js                    # 默认用技能自带客户端
node scripts/update-phone-client.js --path <其他客户端.js>   # --path 是数据参数，非脚本路径
```

新版下发到 `scripts-from-computer/client/`（覆盖）+ 触发自重启。机制与假死排障见 `自动更新手机客户端.md`。

### `scripts/get-lan-ip.js` — 取电脑局域网 IP

```bash
node scripts/get-lan-ip.js --first
```

手机填 IP 时用。已自动排除虚拟网卡 / Clash fake-ip / 链路本地 / CGNAT；`--json` 看网卡名与 MAC。怎么把它填进客户端、以及连不上的处置，见 `手机连接排障.md`。

## 四、模板库目录

`scripts/tasks/<name>/`：每个任务一个文件夹，内含 `<name>.js`（脚本）与 `TASK.md`（说明书）。
规划时先 `scan-tasks.js` 拿 name+description 挑模板，**选中后才 Read 对应 `TASK.md` 全文**。
**TASK.md 结构、两级读取规范、新建/扩展模板的完整流程见 `AI_新建模板手册.md`。**
