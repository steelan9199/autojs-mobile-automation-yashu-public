# 自动更新手机客户端（PC 一键，免手动）

手机端代码（`autojs-task-phone-client.js`）一旦改动，无需再到手机上手动点运行——PC 侧跑一条命令即可把新版下发并让手机端自重启：

```bash
node scripts/update-phone-client.js            # 更新为 skill 自带的最新客户端
node scripts/update-phone-client.js --path <其他位置的客户端.js>   # 指定其他位置的客户端（相对或技能根相对路径均可，勿写死绝对路径）
```

**机制（自举）**：

1. `update-phone-client.js` 先调 `pc-to-phone.js`，把新版 `autojs-task-phone-client.js` 直接下发到手机最终位置 `scripts-from-computer/client/`（已有则覆盖）。
2. 再 `POST /update-client` 触发手机端 `update_client` 指令：旧实例用 `engines.execScriptFile(新版路径)` 启动新实例。
3. 新实例顶部的 `preventDuplicate`（单实例保护）会自动 `forceStop` 掉旧实例——实现零手动自重启。手机端始终保持唯一一份客户端、唯一 WebSocket 连接。

**关键约束**：首次仍需在手机上手动运行一次 `autojs-task-phone-client.js` 以建立 WebSocket 连接（这是 AutoJS6 的运行入口，PC 无法凭空启动 App 内脚本）。建立连接之后，任何手机端代码改动都可用 `update-phone-client.js` 一键热更新，不再需要手动。

## ⚠️ 只覆盖路线B —— 路线A 必须重打包

执行端客户端有**两条路线、同源双份**，本脚本**只能热更新路线B**：

| 路线 | 文件 | 改动后如何生效 |
|---|---|---|
| B（脚本形态，在用） | `scripts/autojs-task-phone-client.js` | 本脚本一键热更新 ✅ |
| A（APK 形态） | `scripts/autojs-project/autojs-task-client-app/client-core.js` | 必须在手机 AutoJs6 里**重新打包「任务执行器」APK** 并重装 ❌ 无法热更新 |

**改客户端核心逻辑（任务下发 / 回执归因 / prologue 注入 / 工程运行）时，两份都必须同步改**，否则两条路线行为分叉、按哪条路线跑结论就不同。打包时顺手把 `scripts/autojs-project/autojs-task-client-app/project.json` 的 `versionName`/`versionCode` 升一位，避免装机版本号对不上。

> 注意：若手机端客户端已假死（在线但不响应指令，常见于媒体 / 图像操作后引擎残留），`update_client` 指令也发不过去。此时仍需先在手机上手动重跑一次客户端清状态；重跑后恢复一键更新能力。

## 路线A 重打包：具体打哪个目录

**打包在手机上做，PC 帮不上**——APK 打包是 AutoJs6 App 内置功能，PC 侧无法代劳。PC 侧能做的是**把最新源码送到手机工程目录**，这一步下面有命令。

### 路径对照

| 环节 | 路径 |
|---|---|
| PC 侧源码（改这份） | `<skill_dir>/scripts/autojs-project/autojs-task-client-app/` |
| **手机上要打包的工程目录** | `/storage/emulated/0/脚本/autojs-task-client-app/` |
| 打包产物落点 | 上述工程目录下的 `build/` 子目录 |

手机路径的规律：它就在 AutoJs6 的**脚本根目录**（即 `/health` 里的 `scriptBaseDir`，默认 `/storage/emulated/0/脚本`）下一层，目录名与 PC 侧一致。AutoJs6 的「项目」页会自动把脚本根下每个含 `project.json` 的目录识别为一个项目。

### 步骤

**① PC 侧：把最新三件套推到手机工程目录**（`client-core.js` / `main.js` / `project.json`）

```bash
cd <skill_dir> && \
DEST="/storage/emulated/0/脚本/autojs-task-client-app" && \
for f in client-core.js main.js project.json; do \
  node scripts/pc-to-phone.js "scripts/autojs-project/autojs-task-client-app/$f" \
    --target-dir "$DEST" --target-name "$f"; \
done
```

> 覆盖前若该工程正在 AutoJs6 编辑器里打开着，先退出项目再覆盖，避免编辑器缓存旧内容回写。

**② 手机侧：在 AutoJs6 里打包**

1. 打开 AutoJs6 → 侧边栏 →「项目」；
2. 列表里找到 **`autojs-task-client-app`**（这就是「任务执行器」的工程，显示名取 `project.json` 的 `name`）；
3. 进入项目后点工具栏的**打包图标**（部分版本可长按项目卡片唤出「打包」菜单）；
4. 打包配置页会预填 `project.json` 里的信息（应用名「任务执行器」、包名 `com.taskrunner.client`、版本号、权限清单），确认后点**开始打包**；
5. 完成后按提示安装（会覆盖旧版 APK）；产物同时落在工程目录的 `build/` 下。

### 打包前必查

- **版本号**：`project.json` 的 `versionName` / `versionCode` 必须比装机版本高，否则系统可能拒绝覆盖安装。打包时顺手升一位。
- **签名一致**：用同一个签名（内置密钥库即可）。换签名会导致无法覆盖安装，需先卸载旧版。
- **别双开**：APK（路线A）与 AutoJs6 脚本客户端（路线B）是**两个独立进程**，同时连中继会互相抢连接。切到 APK 形态时，先把 AutoJs6 里跑的 `autojs-task-phone-client.js` 停掉。
- **首次仍需手动**：APK 装好后首次打开需手动点「启动服务」（权限门禁 + 截图授权），之后可开 `runOnBoot` 自启（`project.json` 的 `launchConfig.runOnBoot`）。
