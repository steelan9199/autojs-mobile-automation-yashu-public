# 部署真实工程（多文件 + 资源）

当任务复杂到单文件模板装不下——拆成多个模块、或工程里还带图片/音频等二进制资源时——用**部署真实工程**模式，而不是把代码塞进一个文件。

**核心设计（two 句话）**：AI 永远在 PC 上把工程组织成多文件（`main.js` + `modules/` + `assets/` + 可选官方 `project.json`），下发时把**整个目录按相对结构部署到手机** `scripts-from-computer/project/<name>/`（PC 传文件用 `/sdcard` 通用别名，运行/删除由手机端按 `getSdcardPath()` 动态拼路径），再触发入口 `main.js` 运行。AutoJS6 的原生 `require()` 与相对路径资源读取按手机文件系统解析，模块/图片/音频直接可用，**二进制资源无需 base64 内联**——这正是"部署真实工程"优于"打包成单文件"的关键（单文件打包无法干净承载图片/音频）。

**工程放哪（约定）**：AI 在 PC 上写的工程统一放在 `<skill_dir>/scripts/autojs-project/<工程名>/`（详见上方「约定」节）——这是 AI 写 AutoJS 工程的默认目录；`deploy-project.js` 直接拿这个目录部署即可。工程内部结构如下：

**PC 工程推荐结构**：

```
<工程目录>/
  project.json        # 可选。name=工程名、main="main.js"、ignore=["node_modules",...]
  main.js             # 入口（被 require / 运行）
  modules/            # 业务模块，内部互相 require('./x')
    autojs-utils.js
  assets/             # 图片/音频等资源，原样下发
    logo.png
    beep.mp3
```

- `main.js` 读参数：**2026-09-16 起工程入口同样注入引导代码**，`__TASK_ID`、`__TASK_ARGS_PATH`（按单参数文件的绝对路径）、`__reportProgress(msg)` 三个全局在工程里**可直接用**，直接 `JSON.parse(files.read(__TASK_ARGS_PATH))` 即可拿到 `--args` 传入的参数（含 `__taskId`/`__template`）。老客户端（或临时绕过中继手动跑）没有这套注入，所以「倒扫 `scripts-from-computer/data/task-args/`、取 `__template === "<工程名>"` 的最新一份」仍要作为兜底保留——现成可抄 `scripts/autojs代码参考例子/autojs-projects/nova/modules/task-args.js`（两级读取，已验证）。
- `main.js` 定位自身目录：用 `files.cwd()`（实测工程运行时的 cwd 即工程目录，**入口注入后仍成立**），或按约定落点 `files.join(files.getSdcardPath(), "脚本", "scripts-from-computer", "project", "<工程名>")` 拼。**不要依赖 `__projectDir`——该变量从未被注入**（全仓库仅出现在防御性 `typeof` 判断里）；资源直接 `files.join(projectDir, "assets/logo.png")` 读。
- 模块互相引用：`require('./modules/autojs-utils')`（**相对写法即可**，运行侧会向 `execScriptFile` 注入工程目录作为 require 搜索路径，详见下方「规范 3」）。**相对 require 的基准是「被加载模块自身所在目录」，不是工程根**（2026-09-16 用非内置模块名三层目录实测确认）：入口（= 工程根）里 `require('./libs/x')` ✓；而 `libs/x.js` 里再写 `require('./y')` 会去找 `libs/y.js`，要回到工程根必须写 `require('../libs/y')`。此外 `require('libs/x')`（裸名带斜杠）与绝对路径也能解析，裸名 `require('x')` 则按模块/插件名查找、找不到直接报 `Module "x" not found`。

**部署 + 运行（一步到位）**：

```bash
cd <skill_dir> && \
  node scripts/deploy-project.js ./my-project --name demo --args '{"count":3}'
```

脚本会：① 读 `project.json` 取 name/main/ignore；② 递归收集文件（跳过 ignore 与隐藏文件）；③ 逐文件经 `send-file-to-phone` 按相对结构落盘到手机 `scripts-from-computer/project/<name>/`；④ 部署完默认触发 `/run-project` 跑入口。只部署不运行加 `--no-run`。

**仅重跑（已部署过）**：

```bash
node scripts/run-project.js demo --args '{"count":5}'
```

**清理已部署工程**：

```bash
node scripts/delete-project.js demo                              # 删 scripts-from-computer/project/demo
node scripts/delete-project.js --path "/sdcard/脚本/任意目录"      # 删任意 sdcard 存储内路径
```

- `delete-project.js` 触发手机端 `delete_project` 指令，用 `files.removeDir` 整目录删除；目标不存在时幂等返回「无需删除」。
- 手机端带安全护栏：传入路径先规范化（解析符号链接与 `..`），只放行 sdcard 存储内路径，拒绝系统目录与整根删除，避免误删。

**两个必做注意点（改动后）**：

- 改完中继源码（含子模块 `scripts/relay/ai-api.js` 等）**必须重启中继**（`curl -X POST localhost:9421/shutdown` 后重跑 `node scripts/autojs-relay-server.js`），否则新端点/新逻辑不生效；
- 改完手机端 `autojs-task-phone-client.js` 后，**用 `update-phone-client.js` 一键热更新**（无需手动），否则手机不认新指令。

**工程代码编写规范（三个硬约束，范本 `autojs-min-project-template` 已内置，写自己的工程照做）**：

1. **严格 ES5 / var only**（通用规则见《编码强制规范》）：工程特有风险——AutoJS6 工程内 `require` 解析模块遇 ES6 语法会直接抛错，整个 `main.js` 加载即崩且**不触发 `events.on('exit')` 回传**，表现为任务单静默失败/超时（排查极难）；
2. **入口必须回传结果**：`main.js` 末尾按 §5.4 标准回执骨架收尾（`events.on("exit")` + 广播 `autojs_result`，见 `references/AI_新建模板手册.md`），把业务结果装进 `result` 对象（**默认失败态**，任何异常路径都回传有意义的信息，不要留"未执行"的真空）；
3. **相对 require 靠运行侧注入的 `config.path` 生效**：工程内模块互相 `require('./modules/autojs-utils')` 能解析，是因为 PC 侧 `run_project` 调用 `engines.execScriptFile(入口, { path: projectDir })` 把工程目录注入为 require 搜索路径——**工程代码保持相对写法，不要手写绝对路径 require**；且相对基准是「被加载模块自身所在目录」（见上方说明，深层模块回退要用 `../`）。
4. **入口注入与运行期临时文件（2026-09-16 起）**：`runProject` 会把入口源码内联进工程目录下的临时入口 `__autojs-entry-<taskId>.js`（`'ui';` 指令仍置首行）后执行，目的是与单文件模板一致地注入 `__TASK_ID` / `__TASK_ARGS_PATH` / `__reportProgress`，并让工程回执**自动带上 `__taskId`**（按单精确归位，任务重叠也不会串号）。对工程代码透明：`files.cwd()` 仍是工程目录、相对 require 基准不变（`__autojs-entry-*.js` 就在工程目录里）。两点可见差异，知悉即可：
   - `engines.myEngine().source` 显示的是这个临时入口名（不是 `main.js`），用 source 认引擎时别只认 `main.js`；
   - 工程目录里会留下 `__autojs-entry-*.js`（客户端启动时清理上一会话的、同工程再次运行时清上一轮的），不必手工维护，**也不要把它当工程源码去改**。
5. **要拉"独立引擎"的子脚本，用注入的 `__spawnSub(路径[, 参数文件])`（2026-09-16 起注入，真机实测通过）**：
   直接 `engines.execScriptFile(子脚本)` 起来的引擎**没有注入前缀**，它的回执就是无主回执，只能靠客户端兜底归因 —— 两个子引擎并发时仍会串号。改用 `__spawnSub` 后，**子引擎自动带父任务号**，回执按单精确归位：

   ```js
   /* 需要独立引擎时（长驻脚本 / UI 脚本 / 不想阻塞主流程） */
   var exec = __spawnSub("/sdcard/脚本/scripts-from-computer/temp/child.js");
   /* 相对路径按 files.cwd() 解析；第二个参数可给子脚本自己的参数文件 */
   var exec2 = __spawnSub("./child.js", "/sdcard/.../child-args.json");
   ```

   实现语义（知道这些就够，不必读源码）：读子脚本源码 → 在内存里拼上**同款注入前缀**（`__TASK_ID` / `__TASK_ARGS_PATH` / `__reportProgress` / 打标代理 / `__spawnSub` 自身）→ `engines.execScript(文件名, 源码, { path: 子脚本所在目录 })` 执行。因此：

   - **不落临时文件**；`require` 基准 = 子脚本所在目录（实测子脚本里 `require('./sibling')` 正常命中）；`files.cwd()` = 子脚本目录；
   - 子脚本首行的 `'ui';` 之类的指令会被**自动提到最前**（否则被注入前缀挤走后静默失效）；
   - 第二个参数省略时，子脚本继承父的 `__TASK_ARGS_PATH`（子脚本通常就是父的子模块，共用参数最省事）；
   - 返回 `ScriptExecution` 对象（可 `.getId()`）；注入失败会自动回退 `engines.execScriptFile`，不会把工程搞挂；
   - **任意深度**：子引擎里同样有 `__spawnSub`，孙脚本依然带父任务号（真机实测通过）。
   - 子引擎的 `engines.myEngine().source` 形如 `$engine/<文件名>.js`（**没有真实文件路径**）——用 `source` 过滤/认引擎时要预料到会多出这类引擎。
   - 只覆盖「用 `__spawnSub` 拉起的」子脚本：第三方库内部直接调 `engines.execScriptFile` 的仍无 tag，兜底归因不能撤。**顺带一条反面结论**：不要试图包装 `engines.execScriptFile` 让它自动注入 —— 该属性 `configurable=false`，`Object.defineProperty` 必抛 `无法将 "execScriptFile" 的 configurable 属性由 false 修改为 true`（真机实测），这也是 `__spawnSub` 走"显式调用"而非"透明包装"的原因。
