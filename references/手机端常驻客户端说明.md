# 手机端常驻客户端与连接状态悬浮球

## 客户端概览

文件：`scripts/autojs-task-phone-client.js`（用户复制到手机 AutoJs6 运行，常驻保活、断线自动重连）。

职责清单：

1. 连接电脑 WebSocket 中继服务器，常驻保活、断线自动重连（间隔 `RECONNECT_INTERVAL = 3000`ms）；
2. 处理中继下发的指令：`capture`（截屏上传）/ `run`（下载并执行任务模板）/ `run_project`（运行已部署工程）/ `stop_task`（按 taskId 强杀任务引擎）/ `update_client`（自更新重启）/ `delete_project`（删除工程）；
3. 转发子脚本经 `events.broadcast` 回传的回执（带注入 `__taskId` 的按 `task_result` 精确归位到任务单，无主回执走旧通道兜底）与 `__reportProgress` 的进度（`task_progress`），并对运行中任务每 10 秒上报心跳（`task_alive`）；
   - **回执打标机制（2026-09-16 修复）**：注入的 prologue 用 `Object.defineProperty(events,"broadcast",{value: JS代理})` 遮蔽广播对象，凡 `autojs_result` 自动补 `__taskId`。此前那套「给 `events.broadcast.emit` 赋值」的写法**从未生效**（`events.broadcast` 是强类型 Java 对象，赋值抛 `InternalError`，被 `catch` 吞掉），导致所有回执都是无主的、在任务时间重叠时被错误归因（实测受害任务单 6.5s 被前一个任务的迟到回执顶替）。
   - **无主回执的兜底归因**：`attributeUntaggedTask()` 现在**优先归给「引擎已退出」的最新任务**（发出回执的引擎通常刚结束），无此类候选才退回「最新未决任务」。**第三方库内部直接** `execScriptFile` 拉起的子脚本仍无 tag，靠这条兜底。
   - **子脚本另起引擎请用注入的 `__spawnSub`**（2026-09-16 加入 prologue）：客户端已完成打标，写脚本只需调它，**完整语义与边界见 `AI_AutoJS_编码细则.md` §2.3.1**。
4. 屏幕常驻「连接状态悬浮球」（下文重点）。

启动前置四项权限（缺一不可）：无障碍、截图（启动时自动弹窗申请）、悬浮窗、后台运行。

> 任务单（taskId）全链路、任务登记表与落盘的设计详见 `scripts/relay/ARCHITECTURE.md` 第 10 节；本文只讲客户端自身行为。

## 连接状态悬浮球

一个可拖动的圆形悬浮窗，实时展示手机与电脑的连接状态。改悬浮球只动 `scripts/autojs-task-phone-client.js` 里「连接状态悬浮球」一节。

### 三色状态

| 颜色 | 含义 | 判定 |
|------|------|------|
| 🔴 红 | 未连接（含启动初期、断线重连中） | `isConnected === false` 且无任务 |
| 🟢 绿 | 与电脑连接正常 | WebSocket 已打开且无任务 |
| 🔵 蓝 | 电脑任务执行中 | `busyCount > 0`（run / run_project / capture / delete_project 任一进行中） |

蓝色判定机制：任务开始 `orbBusyInc()` 计数 +1，完成 `orbBusyDec()` -1；收尾触发点有三类——子脚本回执（`autojs_result` 广播，带注入的 `__taskId` 精确归位）、引擎死亡检测（连续 2 个心跳周期不在 `engines.all()` 且无回执，按失败收尾）、按单强杀（`stop_task` 指令）。**看门狗**：busy 持续超 5 分钟（`ORB_BUSY_WATCHDOG`）自动清零退出蓝色，但每个心跳周期会刷新计时——所以**长任务跑多久就显蓝多久**，看门狗只兜底「客户端整个卡死」的情形。

### 视觉与交互

- **径向渐变发光球**：中心最不透明（alpha 217）→ 亮核边缘（alpha 102，占半径 55%）→ 外边缘全透明；直径 44dp（`ORB_SIZE_DP`）；
- **呼吸感**：整体透明度 45%↔100% 正弦脉动，周期 2.2 秒（`ORB_BREATH_PERIOD` / `ORB_BREATH_MIN`），三态下都不停歇；
- **拖动**：手指按住可拖到屏幕任意位置（范围限制在屏幕内）；
- **自动吸附**：松手 1 秒（`ORB_SNAP_DELAY`）后，200ms 补间动画（`ORB_SNAP_DUR`）吸附到最近的左/右屏幕边缘——只把透明外缘藏进边缘（`orbEdgeTuck` ≈ 直径 22.5%），露出约 90%（≥2/3），亮核完整贴边、始终可再拖出；上下不吸附，保持拖放高度；
- **初始位置**：右侧边缘、屏幕高度 25% 处。

### 生命周期

- 脚本 `exit()` 时经 `events.on("exit")` 自动关闭悬浮窗；引擎被强杀时 AutoJs6 自行清理该引擎的悬浮窗（双保险）；
- 热更新重启（`update_client` → 新实例 `preventDuplicate` 停旧实例）：旧球随旧引擎消失，新球由新实例自动重建，**无需手动处理**；
- 悬浮窗权限未授予时创建失败只打日志、不阻断客户端主流程（球消失但任务功能正常）。

### ⚠️ 关键排障点：截图里悬浮球必然是蓝色

截屏（`GET /screenshot`）本身就是一次任务：客户端收到 capture 指令**先变蓝、再抓屏**。所以**经中继拍的每张截图里悬浮球一定是蓝色**——这是设计使然，不是故障，**不能也不需要据此判断连接/任务状态**。同理，经 `run` 下发的任何截图模板拍到的也是蓝色。

红/绿两色与蓝色走同一条渲染路径（仅 RGB 不同），蓝色正常即证明整条状态机正常；绿/红需用户肉眼确认（如关闭电脑中继后约 3 秒内变红）。

### 可调常量（均在客户端「连接状态悬浮球」一节顶部）

| 常量 | 默认值 | 说明 |
|------|--------|------|
| `ORB_SIZE_DP` | 44 | 球体窗口边长（dp） |
| `ORB_CORE_STOP` | 0.55 | 亮核半径占比，之外渐变到全透明（同时决定吸附藏边宽度） |
| `ORB_BREATH_PERIOD` | 2200 | 呼吸周期（ms） |
| `ORB_BREATH_MIN` | 0.45 | 呼吸最低整体透明度 |
| `ORB_SNAP_DELAY` | 1000 | 松手后多久吸附（ms） |
| `ORB_SNAP_DUR` | 200 | 吸附动画时长（ms） |
| `ORB_BUSY_WATCHDOG` | 300000 | busy 看门狗阈值（ms） |
| `ORB_COLORS` | 红/绿/蓝三组 RGB | 三态颜色（`colors.argb` 加 alpha，勿写 0xAARRGGBB 字面量） |

## 改动后如何生效

客户端有**两条路线、同源双份**：路线B 是脚本形态（`scripts/autojs-task-phone-client.js`，已在用），路线A 是 APK 形态（`scripts/autojs-project/autojs-task-client-app/`）。
**改核心逻辑必须两份同步改**——只改 B，重打包出的 APK 会带回老 bug（2026-09-16 BUG-01 就漏过一次）。

热更新命令、A/B 路径对照、路线A 重打包步骤、假死处置 —— 全部见 `自动更新手机客户端.md`，本节不重复。
改客户端代码前先读 `references/AI_AutoJS编码强制规范.md`（严格 ES5、UI 线程零阻塞、渐变颜色 `int[]` 防炸写法等）。
