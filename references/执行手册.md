# 执行手册（任务开始读一次）

> **本文件是流程层**：SKILL.md 只留硬约束与授权提示——那两类漏读即出事（不可逆 / 断连 / 白跑），必须待在常驻层，因为常驻层是唯一不会被漏读的层；其余流程性内容全在这里。
> **读一次就够**：不要每轮重读、不要整篇回读。硬约束与授权提示在 SKILL.md，本文件不重复。

**依赖前提**：`cd scripts && npm install`

## 一、执行 SOP

**第 0 步 健康检查（中继存活 SOP）**
`curl -s http://localhost:9421/health` —— `"phone":"connected"` → 进第 1 步；`"disconnected"` → 按 `references/手机连接排障.md` 五步流程**主动带用户连上**，不许只甩一句"请连接手机"。**只有返回「连接拒绝/无响应」才启动中继**（已在跑绝不重启，会踢掉已连手机）；启动**必须用受管后台任务，严禁命令末尾 `&`**（会在本轮结束时被回收，下轮手机就超时连不上）。详见 `references/中继存活SOP.md`。

**第 1 步 拆解（两级读取）**
先 `node scripts/scan-tasks.js` 拿全部模板 name+description 挑模板，选中后**才** Read 该 `scripts/tasks/<name>/TASK.md` 全文。模板覆盖不了的才现场写脚本到 `temp/`，**写前必读** `references/AI_AutoJS编码强制规范.md`（**只读顶部「必读核心」**，命中具体报错再查 `references/AI_AutoJS_编码细则.md`）与 `references/现场脚本规范.md`；凡调 `captureScreen()`/`ocr()` 的脚本**必须内置授权弹框前置代码**（`references/截图权限与弹框处理.md`）。

**第 2 步 逐步下发**
`cd <skill_dir> && node scripts/run-task.js <模板名> --args '{...}'`

- `ok:1` → 下一步；`ok:0` → 换策略重试**一次**（如 tap-text 找不到就截图看屏），仍失败则终止并汇报卡点；
- **长短任务判定**：原子操作（点/滑/截屏/开 App）→ 短，默认同步等待；耗时随规模变或不可预估 → 长，加 `--wait 0` 立返 taskId，再用 `--status` 查进度、`--stop` 强杀。模板描述末尾 `[平均 X 秒]` 是实测耗时，直接据此判断；
- 界面跳转后插一步 `wait`（500~1500ms）再操作下一步；
- 回执超限（`resultTruncated:true`，在**外层**、与 `result` 同级）→ `result` 是被截断的**残缺 JSON，不可 `JSON.parse`**，只能当纯文本预览读；全文在 `resultFile` 落盘路径，**严禁整段读进上下文**，用 grep 按行 offset 取片段。

**第 3 步 看屏幕** → 见下「二、看屏回退链」，逐级实测，别一上来就截屏。

**第 4 步 终态一次性汇报** → 一句话结果，或"卡在第 N 步 + 原因 + 手动补救建议"。**中间过程不打扰用户。**

## 二、看屏回退链（省 token 优先，逐级实测，不跳级）

1. **控件树** `inspect_control_by_*`：取 `text`/`id`/`desc` —— 最准最省。**禁止回传整棵 UI 树 JSON**。控件树不全 / APP 屏蔽无障碍 → 下一级。
2. **OCR** `ocr` 模板：文字多的屏带 `{"query":"关键词"}` 源头过滤，`detail:true` 仅在确需坐标时用。纯图形界面 / 文字不足以判断 → 下一级。
3. **截图 + 模型直读**：`curl -s http://localhost:9421/screenshot` 落 PC PNG 后读图。最贵，仅当前两级不行时用；已知控件包围盒时用 `crop-screenshot` 只裁该区域。模型不支持多模态则本层不可用 → 直接问用户。

> 截图角落彩色圆点是**连接状态悬浮球**（红未连/绿已连/蓝执行中）。经中继拍的每张截图里它恒为蓝色，属正常，勿据此误判连接状态。

## 四、成本纪律（每次执行都适用）

1. **只传路径不传代码**：模板存 PC，下发只传 `path`+`args`；回执默认 `{ok:1}` / `{ok:0,err}`，不得要求回传整棵 UI 树或大段文本。
2. **全自动连跑**：中间步骤静默执行，终态一次性汇报。
3. **两级读取 + 2K 预算**：规划只读 description，选中才读正文；回执超 2000 字符自动截为预览 + 落盘路径。
4. **大文档只读命中的那一段**：`references/` 里超过 9,000 字符的文档一律先 Grep 标题定位，用 offset/limit 只读相关小节，禁止通读。
5. **本手册与 SKILL.md 每次任务各读一次即可**，不要每轮重读。
6. **改完技能必跑**：`node scripts/skill-cost.js` —— 常驻层超线就必须处理（外移或压缩），判据见 `references/技能维护与成本判据.md`。

## 五、退出码

`0` 成功 · `1` 参数/通用失败 · `2` 请求失败或手机未连接 · `3` 文件不存在 · `4` 环境不满足 · `5` 需要授权（见 SKILL.md「授权提示」）。

> ⚠️ **超时也是退出码 `0`**（2026-09-16 实测）：轮询 `--wait` 秒数内未终态时，进程以 `0` 退出，stdout 却是 `{"success":false,"timeout":true,"taskId":...,"status":"running",...}`，任务仍在手机上跑。
> **所以判成败只看 stdout，不要看退出码**——`exit 0` 不等于成功。正确读法：先取 `success`（`false`+`timeout:true` → 用 `--status` 续查；`false` 且非 timeout → 真失败），再看 `result.ok` 定业务成败（见 SKILL.md 硬约束 3）。
