# 手机连接排障（手机未连接时的处理）

触发条件：第 0 步 health 返回 `{"phone":"disconnected"}`。

## 一、判定规则（唯一一条，无分支）

> **中继已启动 → 1 秒轮询复查 → 满 5 秒仍 `disconnected` → 无条件输出下面的统一引导。**

| 状态 | 动作 |
| --- | --- |
| 中继没起（连接拒绝 / 无响应） | **不引导用户**——按 `references/中继存活SOP.md` 用**受管后台任务**拉起中继，手机端看门狗会自动连回 |
| 5 秒宽限内连上 | 静默放行，继续原任务，不打扰用户 |
| 5 秒后仍 `disconnected` | 触发「二、引导话术」 |

**实现口径**：不要傻等 5 秒。每 1 秒查一次 health，**一连上立刻放行**；满 5 秒仍未连上才引导——秒连的场景零延迟。

⚠️ 判读务必**精确匹配整串 `"phone":"connected"`**：`connected` 是 `disconnected` 的**子串**，用子串匹配（如 `grep -q connected`）会把「未连接」误判成「已连接」，直接跳过引导、还当成连上了继续下发任务（本机实测踩过这个坑）。

## 二、引导话术（恒定 7 步，一次到位）

> **硬要求**：必须**完整、明确**地输出全部 7 步。普通用户不知道脚本文件在哪、不知道要开哪些权限——省掉任何一条，用户就卡死在那一步。**不许只甩一句"请连接手机"。**

### 第 1 步 · 先对中继 IP（前置必查）

中继是服务端，手机端唯一的连接入口就是客户端里的 `SERVER_IP`——**这个值一错，手机 100% 连不上**。所以先对 IP，再谈别的。

1. **AI 自己跑取局域网 IP**（不要叫用户自己去查）：
   ```bash
   node <skill_dir>/scripts/get-lan-ip.js --first
   ```
   拿到形如 `192.168.x.x` 的地址（脚本已自动排除虚拟网卡 / Clash fake-ip / 链路本地 `169.254.x` / CGNAT `100.64.x`）。加 `--json` 可看网卡名与 MAC。
   ⚠️ **别用 `ipconfig`**（GBK 乱码，grep 报 Binary file matches）**或 PowerShell `Get-NetIPAddress`**（本机可能无输出），也不必自己解析——脚本零编码坑。
2. ⚠️ 局域网 IP 是 **DHCP 动态分配**，换网络 / 重连就变：**每次现取，不要写死进代码**，也不要复述文档里的历史值。
3. 把该 IP **原样写进话术**，并给出**傻瓜改法**：
   - 文件：`autojs-task-phone-client.js`（手机端常驻客户端）；**同时把该文件的绝对路径发给用户**，否则他找不到文件；
   - 位置：用 AutoJs6 打开它，搜 `var SERVER_IP =`（在「配置」一节），形如 `var SERVER_IP = "192.168.0.41";`；
   - 操作：把引号里的值换成刚取到的 IP，**保存后再点运行**；
   - 端口 `SERVER_PORT` 保持 `9421` 不动（除非改过约定端口）。

### 第 2 步 · 手机装 AutoJs6

没装就给下载地址，让用户自己下载安装：
`https://github.com/SuperMonster003/AutoJs6/releases`

### 第 3 步 · 把常驻脚本弄到手机，用 AutoJs6 运行

告诉用户：**把 `autojs-task-phone-client.js` 这个文件弄到手机上，然后用 AutoJs6 打开并运行它。**
- ⛔ **必须把「绝对路径」发给用户** —— 普通用户找不到这个文件在哪。AI 输出时把下行的 `<skill_dir>` 换成运行时真实路径（形如 `C:/Users/Administrator/.workbuddy/skills/autojs-mobile-automation-yashu`），**禁止把 `<skill_dir>` 占位符原样发给用户**：
  `<skill_dir>/scripts/autojs-task-phone-client.js`
- **只说"弄到手机上"即可**，不必教用户用微信还是数据线。

### 第 4 步 · 开权限

逐项念给用户，详见本文末「补充：手机端四项权限怎么开」：无障碍 / 悬浮窗 / 后台运行（电池白名单）。
⚠️ 脚本启动时会申请**截图权限**，会出现授权申请弹窗，要提醒用户点"立即开始"（部分 ROM 文案是"开始截图"）；缺它则截图类任务全部失败。

### 第 5 步 · 确认同一 WiFi

手机和电脑必须连**同一个 WiFi**。

### 第 6 步 · 收尾：等用户回报

让用户连上后回一句"连上了"；AI **再跑一次 health** 确认 `phone: "connected"` 后才继续任务。

### 第 7 步 · 二级出口（兜底，防止死胡同）

若用户把 IP、App、脚本、权限**全部做齐后仍连不上**，让他回一句"还是连不上"，AI 再带他查下一层（典型：AutoJs6 被系统杀后台、手机与电脑不在同一网段、客户端脚本根本没在跑）。
**⛔ 不要给完前 6 步就结束对话**——没有二级出口就是死胡同。

### 给用户的引导话术（可整段复制，`<>` 处按实情替换）

> 手机需要装 AutoJs6、再跑一份脚本才能和我连上，请一次做完下面几步：
> 1. **对 IP（最关键）**：你电脑的中继 IP 是 `<实时取到的IP>`。用 AutoJs6 打开 `autojs-task-phone-client.js`（若手机里还没有这个文件，先看第 3 条把它弄过去），搜 `var SERVER_IP`，把引号里改成 `<实时取到的IP>`，保存后运行；
> 2. 手机装 AutoJs6（没装的话从这下载安装：https://github.com/SuperMonster003/AutoJs6/releases）；
> 3. 把电脑上的文件 `autojs-task-phone-client.js`（完整路径：`<真实绝对路径>`）弄到手机上，用 AutoJs6 打开并运行它；
> 4. 给它开 3 项权限：无障碍、悬浮窗、后台运行（省电策略设"无限制"）；脚本启动弹出截图授权时点"立即开始"；
> 5. 手机和电脑连同一个 WiFi。
> 弄好后回我一句"连上了"；**如果全都做齐了还是连不上，也回我一声"还是连不上"，我再带你往下查。**

## 三、覆盖边界（这套机制盖不住什么）

- **只兜「真断线」**：即 health 返回 `disconnected` 的情形——中继没被拉起、网络闪断、客户端脚本没在跑。
- **不兜「半开假死」**：连接没断、但指令发不进去时，**health 显示的是 `connected`**，5 秒判定根本不会触发——本机制对它是空转。假死由客户端自身的看门狗兜底，不由引导话术兜底。
- **不探测原因**：5 秒到点后一律输出同一套引导，不查到底是 IP 不对还是客户端没跑。用户照做即可；做齐仍不行走**第 7 步二级出口**。

## 补充：手机端的权限怎么开（缺一不可）

前提是手机上已安装 **AutoJS6** 应用（官网 https://docs.autojs6.com/#/ ）。权限：

1. **无障碍服务**：设置 → 应用 → AutoJs6 → 无障碍 → 开启；
2. **悬浮窗权限**：设置 → 应用 → AutoJs6 → 权限管理 → 悬浮窗 → 允许；
3. **后台运行**：设置 → 应用 → AutoJs6 → 省电策略设为“无限制”，并在自启动管理中允许自启动（否则锁屏/切后台后常驻客户端被系统杀掉，任务中断）。

## 补充：断线自愈与假死

- 客户端内置**重连看门狗 + 应用层心跳**（1 秒巡检、3 秒重试、30 秒无 pong 判假死强制重连）：中继重启、网络闪断、电脑休眠恢复，手机都会自动回归，**不需要人工干预**。
- 仅当客户端引擎本身死亡/假死（手机没在跑脚本、AutoJs6 被杀）时才需要走上面的引导流程（第二节）：连上一次后，后续改代码可用 `update-phone-client.js` 一键热更新。
