## 条目原文（全量搬移，未删改）

- **把客户端当普通脚本停掉（最高频事故）**：失败清场时 `list-running-scripts` 会把执行端本体一并列出，它**看着就是个普通脚本**。识别：回执里 `isClient:true` / 在 `clientIds` 里 / `source` 是相对路径 `main.js` 且 `cwd` 在 `/data/user/0/<包名>/files/project`（路线A），或 `source` 为 `autojs-task-phone-client.js`（路线B）。**它不是可停目标**；`stop-script-by-id` 会拒停并回 `ok:0 + blockedClient`，此拒绝是护栏不是 bug。
- **熄屏/锁屏**：截全黑帧 + 剪贴板读空 + OCR 异常，而 `open-app` 却"假成功"（`am start` 不需亮屏）→ 让用户点亮解锁后重试，别往脚本 bug 方向排查。
- **setInterval 保活分场景**：为"等任务回执"而保活不要做——经 `/run` 下发的脚本由中继托管，正常 exit 即回执；但**悬浮窗/常驻 UI 类脚本必须 `setInterval(空函数, 3000)` 保活**，否则脚本引擎随主线程结束而退出，悬浮窗瞬间被销毁（用户约定的标准做法）。
- **UI 常驻任务关残留窗口，`--stop` 无效**：建好即回执后任务单已终态，`--stop` 返回 `alreadyFinished` 而引擎仍常驻、窗口还在 → 正确链路：`list-running-scripts` 拿实时引擎 id → `stop-script-by-id` 停掉（见 `references/引擎_self_识别与isSelf判定.md` §8）。
- **UI 树查找慢**：界面层级深时 `tap-text` 等会慢，属正常，等回执即可。
- **回执"串号"（任务单内容属于别的任务）**：回执靠 `__taskId` 精确归位；客户端 2026-09-16 已修好两处——① prologue 用 `Object.defineProperty` 遮蔽 `events.broadcast` 自动补 tag（旧写法给 Java 方法赋值永不生效，异常被吞）；② 无主回执的兜底归因改为「优先引擎已退出的最新任务」。**若仍见到串号，先跑 `node scripts/update-phone-client.js` 把手机端客户端升到最新**；工程内 `execScriptFile` 拉起的子引擎脚本不带 prologue，其回执仍靠上述兜底归因（并发的子引擎任务要串行）。
- **工程引擎的 `source` 不是 `main.js`**：2026-09-16 起 `run_project` 会把入口内联进工程目录下的临时入口 `__autojs-entry-<taskId>.js` 再执行（为注入参数、让回执带 tag）。用 `source` 过滤/认引擎时别只认 `main.js`；`isClient` 判定不受影响。临时入口文件由客户端自动清理，别当源码改。
- **改客户端核心逻辑必须两条路线同步**：`scripts/autojs-task-phone-client.js`（路线B，`update-phone-client.js` 热更新）与 `scripts/autojs-project/autojs-task-client-app/client-core.js`（路线A，需重新打包 APK）是同源双份，核心逻辑逐段对应。**只改一份是历史事故源**（2026-09-16 BUG-01 修复就漏改过 client-core.js）。
- **子脚本要另起引擎：用 `__spawnSub`，别直接 `execScriptFile`**：直接拉起 → 子引擎没有注入前缀 → 回执无 tag → 只能靠客户端「优先归给引擎已退出的最新任务」兜底，**两个子引擎并发必然串号**。改用注入的 `__spawnSub(路径[, 参数文件])`（2026-09-16 起，真机实测），子引擎回执自动带父任务号、`require` 基准 = 子脚本目录、首行 `'ui';` 自动提到最前，且任意深度有效。**别试图包装 `engines.execScriptFile` 让它自动注入**——该属性 `configurable=false`，`defineProperty` 必抛。见《部署真实工程.md》规范 5。
- **`source` 形如 `$engine/<名>.js` 的引擎 = `__spawnSub` 拉起的子引擎**（内存源码，**没有真实文件路径**）。按 `source` 过滤/认引擎时要把这类算进去，别当成"未知异常引擎"。
- **⛔ 脚本顶层别用 `R` / `L` 作变量名**（2026-09-16 真机实测）：这俩是 AutoJS6 **预置全局名**（`typeof R === "object"`；`A`~`K`/`M`~`Z`/`$`/`_` 实测均空闲）。脚本**顶层**写 `var R = {...}` 赋值会**静默失败**（非严格模式不报错），于是 `R.dirs` 落到内置宿主对象成员上（是 number），`R.dirs.push(...)` 抛 `TypeError: push 是 number 而非函数.`；若该行没有 try/catch，脚本会在末尾 `emit` 之前终止 → 中继只报「引擎已退出但未收到回执」，**完全没有错误信息**，极易误判成 API 不存在/网络问题/客户端假死。**函数内部**的 `var R` 是局部变量、安全（`skill-tester` 大量用 `var R = ctx.reporter;` 且正常）。排查手法见 `references/AI_AutoJS编码强制规范.md` §1.7 与 §3.1。
- **别凭记忆猜全局名，也别用 `Object.keys` / `for...in` 判存在（2026-09-16 真机实测）**：全局对象只有 `Object.getOwnPropertyNames(global)` 是完整清单（615 条），`Object.keys` / `for...in` 少 90 条不可枚举项；`runtime.topLevelScope`、`global`、顶层 `this` 是**同一个对象**。三个高频错判：① `$id` / `$text` / `$desc` / `$type` / `$select` **在 AutoJS6 里不存在**（`$` 前缀只有模块别名，如 `$ui` / `$files` / `$app`；选择器简写是 `id()` / `text()` / `desc()`，**不带 `$`**）；② `activity` **不在**全局对象清单上（仅 UI 模式注入），别用清单反推"没有 activity"；③ 探针若写在顶层，脚本自己的 `var` 会混进清单（实测多出 35 个）——探针一律包 IIFE。全清单与判定方法见 `references/AutoJs6_全局变量判定与实测清单.md`。
- **`files` 模块没有 `getLength` / `getLastModified` / `size`**：这三个都是 `undefined`，调它抛 `TypeError: 无法找到函数 xxx.`。取文件大小/时间一律用 `new java.io.File(p).length()` / `.lastModified()`（`files.listDir`/`isDir`/`exists`/`read`/`write`/`join`/`remove`/`ensureDir` 正常可用）。
