## 条目原文（全量搬移，未删改）

- **把客户端当普通脚本停掉（最高频事故）**：失败清场时 `list-running-scripts` 会把执行端本体一并列出，它**看着就是个普通脚本**。识别：回执里 `isClient:true` / 在 `clientIds` 里 / `source` 是相对路径 `main.js` 且 `cwd` 在 `/data/user/0/<包名>/files/project`（路线A），或 `source` 为 `autojs-task-phone-client.js`（路线B）。**它不是可停目标**；`stop-script-by-id` 会拒停并回 `ok:0 + blockedClient`，此拒绝是护栏不是 bug。
- **熄屏/锁屏**：截全黑帧 + 剪贴板读空 + OCR 异常，而 `open-app` 却"假成功"（`am start` 不需亮屏）→ 让用户点亮解锁后重试，别往脚本 bug 方向排查。
- **setInterval 保活分场景**：为"等任务回执"而保活不要做——经 `/run` 下发的脚本由中继托管，正常 exit 即回执；但**悬浮窗/常驻 UI 类脚本必须 `setInterval(空函数, 3000)` 保活**，否则脚本引擎随主线程结束而退出，悬浮窗瞬间被销毁（用户约定的标准做法）。
- **UI 常驻任务关残留窗口，`--stop` 无效**：建好即回执后任务单已终态，`--stop` 返回 `alreadyFinished` 而引擎仍常驻、窗口还在 → 正确链路：`list-running-scripts` 拿实时引擎 id → `stop-script-by-id` 停掉（见 `references/引擎_self_识别与isSelf判定.md` §8）。
- **UI 树查找慢**：界面层级深时 `tap-text` 等会慢，属正常，等回执即可。
- **回执"串号"（任务单内容属于别的任务）**：回执靠 `__taskId` 精确归位；客户端 2026-09-16 已修好两处——① prologue 用 `Object.defineProperty` 遮蔽 `events.broadcast` 自动补 tag（旧写法给 Java 方法赋值永不生效，异常被吞）；② 无主回执的兜底归因改为「优先引擎已退出的最新任务」。**若仍见到串号，先跑 `node scripts/update-phone-client.js` 把手机端客户端升到最新**；工程内 `execScriptFile` 拉起的子引擎脚本不带 prologue，其回执仍靠上述兜底归因（并发的子引擎任务要串行）。
- **工程引擎的 `source` 不是 `main.js`**：2026-09-16 起 `run_project` 会把入口内联进工程目录下的临时入口 `__autojs-entry-<taskId>.js` 再执行（为注入参数、让回执带 tag）。用 `source` 过滤/认引擎时别只认 `main.js`；`isClient` 判定不受影响。临时入口文件由客户端自动清理，别当源码改。
- **改客户端核心逻辑必须两条路线同步**：`scripts/autojs-task-phone-client.js`（路线B，`update-phone-client.js` 热更新）与 `scripts/autojs-project/autojs-task-client-app/client-core.js`（路线A，需重新打包 APK）是同源双份，核心逻辑逐段对应。**只改一份是历史事故源**（2026-09-16 BUG-01 修复就漏改过 client-core.js）。
- **子脚本要另起引擎：用 `__spawnSub`，别直接 `execScriptFile`**：直接拉起 → 子引擎没有注入前缀 → 回执无 tag → 两个子引擎并发必然串号；改用注入的 `__spawnSub(路径[, 参数文件])` 后子引擎回执自动带父任务号。**别试图包装 `engines.execScriptFile` 让它自动注入**（`configurable=false`，`defineProperty` 必抛）。完整语义见 `AI_AutoJS_编码细则.md` §2.3.1。
- **`source` 形如 `$engine/<名>.js` 的引擎 = `__spawnSub` 拉起的子引擎**（内存源码，**没有真实文件路径**）。按 `source` 过滤/认引擎时要把这类算进去，别当成"未知异常引擎"。
- **⛔ 脚本顶层别用 `R` / `L` 作变量名**（2026-09-16 真机实测）：这俩是 AutoJS6 **预置全局名**（`typeof R === "object"`；`A`~`K`/`M`~`Z`/`$`/`_` 实测均空闲）。脚本**顶层**写 `var R = {...}` 赋值会**静默失败**（非严格模式不报错），于是 `R.dirs` 落到内置宿主对象成员上（是 number），`R.dirs.push(...)` 抛 `TypeError: push 是 number 而非函数.`；若该行没有 try/catch，脚本会在末尾 `emit` 之前终止 → 中继只报「引擎已退出但未收到回执」，**完全没有错误信息**，极易误判成 API 不存在/网络问题/客户端假死。**函数内部**的 `var R` 是局部变量、安全（`skill-tester` 大量用 `var R = ctx.reporter;` 且正常）。排查手法见 `references/AI_AutoJS编码强制规范.md` §1.7 与 §3.1。
- **别凭记忆猜全局名，也别用 `Object.keys` / `for...in` 判存在（2026-09-16 真机实测）**：全局对象只有 `Object.getOwnPropertyNames(global)` 是完整清单（615 条），`Object.keys` / `for...in` 少 90 条不可枚举项；`runtime.topLevelScope`、`global`、顶层 `this` 是**同一个对象**。三个高频错判：① `$id` / `$text` / `$desc` / `$type` / `$select` **在 AutoJS6 里不存在**（`$` 前缀只有模块别名，如 `$ui` / `$files` / `$app`；选择器简写是 `id()` / `text()` / `desc()`，**不带 `$`**）；② `activity` **不在**全局对象清单上（仅 UI 模式注入），别用清单反推"没有 activity"；③ 探针若写在顶层，脚本自己的 `var` 会混进清单（实测多出 35 个）——探针一律包 IIFE；④ **反过来同样致命：你写的名字若恰好是预设全局名，引用会跑到宿主对象上**——真机事故（2026-09-22）：WebView 工程把官方桥写成裸 `web.jsBridge.handle('ping', …)`，而 WebView 变量其实叫 `page`，于是 `web` 命中**全局 `web`（= `$web`，HTTP 模块）**，只报 `TypeError: 无法调用 undefined 的方法 "handle".`，异常被 catch 后只剩 `bridge=off`、页面侧 `$autojs.invoke()` **全部静默失败**（不崩不报错，只是读不到东西）。**`jsBridge` 是 WebView 对象上的属性，不是全局**：桥挂谁身上就写 `谁.jsBridge`。官方示例 `Vue3 + Vant (SFC)` 能跑只因它 `let web = ui['web']` 用局部变量**遮蔽**了全局，同名纯属巧合、**别照抄**。全清单与判定方法见 `references/AutoJs6_全局变量判定与实测清单.md`，机制与命名规则见 `AI_AutoJS_编码细则.md` §1.7。
- **`files` 模块没有 `getLength` / `getLastModified` / `size`**：这三个都是 `undefined`，调它抛 `TypeError: 无法找到函数 xxx.`。取文件大小/时间一律用 `new java.io.File(p).length()` / `.lastModified()`（`files.listDir`/`isDir`/`exists`/`read`/`write`/`join`/`remove`/`ensureDir` 正常可用）。
- **【打包形态】工程内 `.js` 被加密，运行期 `files.read` 读到的是密文（2026-09-20 实测，含 APK 取证）**：AutoJs6 打包 APK 时把工程内**所有 `.js` 文件加密**（APK 里 `assets/project/res/concepts.js` 头部是 `77 01 17 7F` 二进制），只有 `.html` / `.css` / `.json` 等资源是明文原样打包；`main.js` 同样被加密，但它走"脚本"通道被正确解密执行，**所以"能跑"不代表"读得到"**。症状：WebView 类工程中继运行完全正常，**打包后一打开只剩 HTML 骨架那几行字**（顶栏/搜索框/底部 Tab 在，地图与列表全空）——因为运行期读 `.js` 拼页面时拿到密文，内联进 `<script>` 直接语法错误。判别：解出 APK 看条目头部字节（明文 HTML 是 `3C 21 44 4F 43 54 59 50 45` = `<!DOCTYPE`）。**修法：运行期只读 `.html/.css` 这类明文资源**——工程内预合成一份单文件页面（如 `res/page.html`，Node 脚本生成），`main.js` 优先读它，找不到再退回运行期合成；不要用"改名成 `.txt`"以外的方式指望 `.js` 明文落盘。范例：`scripts/autojs-project/ai-video-map/`（`tools/build-page.cjs` + `main.js` 的 `looksEncrypted()` 自检）。附带一条：MT MCP（`http://<手机IP>:8787/mcp`）可解包/改包/重签 APK，是这类"打包后取证"的最快手段；注意其文件策略默认只放行 `/storage/emulated/0/脚本`。

**两条"看着能解、其实没用"的路（2026-09-20 最小工程对照实验，别再花时间试）**：

> **实验台**：`scripts/autojs-project/min-encrypt-test/`（保留着，以后有同类疑问直接重跑，见该工程 `README.md`）。
> **设计**：`data.js` **写进** `assets` 数组、`keep.js` **不写**，两者内容同构作严格对照；另加 `res/index.html` / `res/note.txt` 作明文参照；同一次打包还带上 `"encryptLevel": 0`。
> **探针**：`main.js` 在真机上逐文件读头部 8 字节，判定结果**直接显示在 App 弹窗里**，不用解包就能读数。

- ❌ `project.json` 里 `"assets": [...]` —— **拦不住加密**。判决最硬的一点：**进了白名单的 `data.js` 与没进的 `keep.js`，头部字节完全一样**（`77 01 17 7F 12 12 00 00`），都是密文 —— 这排除了"文件名写错 / 路径对不上"的所有余地。官方对 `assets` 的注释本就是"保留字段，暂时没有作用"；APK 里也**没有生成任何明文副本**（`assets/res/...`、`assets/app.js` 命中 0 条）。
- ❌ `"encryptLevel": 0`（Auto.js **Pro** 的"0-不加密"字段）—— **拦不住加密**。同一次打包里 `main.js`/`data.js`/`keep.js` 三个 js 全密文；更硬的是 **AutoJs6 打包时直接丢弃这个字段**（写回的 `project.json` 里没有它），说明它的 ProjectConfig 根本不认识这个键 —— **该字段属 Auto.js Pro，AutoJs6 不支持**。AutoJs6 对工程内 `.js` 是无条件 AES 加密（密文前写 `EncryptedScriptFileHeader`；密钥 `MD5(packageName+versionName+mainScript)`、IV `MD5(buildId+name)` 前 16 字节 ⇒ **每次打包密文都不同，不可跨版本复用**）。
- ✅ 正解只有一条：`res/page.html` 这类**明文资源**承载体。已实机验证——打成 APK 装到手机后内容完整（地图/47 条/收藏全部正常）。流程固化：改 `res/` → 跑 `node tools/build-page.cjs` → 打包。
- ✅ 判定加密的最快手法（不用解包）：**对比"APK 内条目大小"与本地文件大小**——密文比明文**固定多 16~17 字节**（IV + padding 开销），而 `index.html` / `style.css` 这类资源的大小分毫不差。取头部字节更直接：明文 HTML 是 `3C 21 44 4F 43 54 59 50 45`（`<!DOCTYPE`），密文 js 是 `77 01 17 7F`。
- ⚠️ 附带发现（同次实验）：**打包后的 App 默认没有外部存储权限**——探针想写 `/sdcard/脚本/min-encrypt-report.txt` 抛 `EACCES (Permission denied)`（除非打包时勾了存储权限）。所以打包形态下工程根就是 `files.cwd()` = `/data/user/0/<包名>/files/project`，**别指望打包 App 去 `/sdcard` 读工程副本**（`pickResDir()` 里那条 `/sdcard` 候选在打包形态必然落空，别把它当成救命路径）。
- **【打包形态】加密判定纯按后缀、`.md` 明文（2026-09-22 复现 + 扩样，全矩阵见细则 §10）**：对第 14 条的独立复现，并把后缀覆盖从 3 种扩到 10 种（实验台 `scripts/autojs-project/enc-probe/`，17 文件，装 APK 后运行）。结论一致：**只加密 `.js`，全目录扫描不豁免**（`res/lib.js` 同样密文）。**两条硬对照**：`.txt` 里写真 JS 内容 → **明文**；`.js` 里写纯文本 → **密文** ⇒ 判定只看后缀、与内容无关。**关键新增**：`res/doc.md` **明文** ⇒「外壳 + 按页读 md」方案成立（`.md`/`.json`/`.txt`/`.xml`/`.csv`/`.svg`/`.png` 与无后缀文件均明文）；`require()` 加密 `.js` 仍正常返回（AutoJS 自解密，加密只挡外部读取者）。**打包后把数据交回电脑的通道**：本次报告双写只有 App 私有目录那条成功，实际靠"弹框按钮 `setClip(report)` → 电脑端 `get-clipboard` 读剪贴板 → 落地 `scripts/uploads/*.txt`"取回（1575 字报告完整，已端到端实测）。注意 Android 10+ **后台读不到剪贴板**，AutoJs6 需在前台亮屏。
