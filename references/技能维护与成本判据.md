# 技能维护与成本判据

> **只在改动本技能时读**。日常执行任务不需要本文件。

## 一、先看成本模型（旧版规则错在这）

技能包的体积**不是成本**。成本是「被读进上下文的次数 × 单次体积 × 单价」：

| 通道 | 付费时机 | 倍率 |
| --- | --- | --- |
| A 描述（frontmatter） | 会话开始注入技能目录，**与用不用本技能无关** | 每个会话 ×1 |
| B 常驻层 `SKILL.md` | 技能激活后**每轮对话重发** | 轮数 N |
| C 规划层 `scan-tasks.js` 输出 | 每次规划 1 次 | 每次任务 |
| D `references/*` | 命中场景才读 | 每次任务（可多次） |
| E `tasks/*/TASK.md` | 选中该模板才读 | 每次任务（≤1） |

**关键推论：一段内容一旦移出常驻层，付费次数就从 N 变成 1。** 所以「外移」在 N ≥ 2 时几乎总是净赚——这就是流程层（SOP / 看屏链 / 路由表 / 成本纪律）被下沉到 `执行手册.md` 的原因。

## 二、判据（替代旧版「不属三类事故就写进 references」）

旧版规则**方向对、判据错**，三处硬伤：

1. **缺维度**——只筛严重度，不问「一次任务里会用几次」。留常驻的成本是 `体积 × 后续轮数`，不看频率就会把高频流程误判成"非事故项"外移。
2. **默认外移免费**——外移要付两笔：常驻层必须留的**指针占位**，以及**漏读代价**。常驻层是唯一**不可能被漏读**的层；外移等于把确定性换成概率。旧规则完全没算这两笔。
3. **「禁止净增长」是危险设计**——它逼着作者新增一条安全规则时必须外移等量内容，而外移的可能正是另一条护栏，等于**用 token 规则绑架安全**。上限应该是成本模型的输出，不是法律。

### 采用的判据

一段内容进入常驻层（`SKILL.md`），当且仅当满足以下**任一条**：

- **T1 漏读即事故**：AI 没看见它，会产生**不可逆操作 / 断连 / 白跑**。→ 必须常驻（常驻层是唯一不会被漏读的层）。
- **T2 体积极小且每轮都在用**：例如指向 `执行手册.md` 的那一行指针。

其余内容一律问这笔账：

```
外移净收益 = 体积 ×（剩余轮数 − 1）× 缓存折扣 − 指针占位 − 漏读代价
```

- **缓存折扣**：宿主若有 prompt cache，常驻层前缀被缓存，每轮边际价大幅低于标价 → **不要拿"体积 × 轮数"当实际省钱对外汇报**，它只是无缓存上限。
- **漏读代价低**（顶多多读几个文档、多截一次屏）→ 外移。
- **漏读代价高**（断连 / 不可逆 / 白跑）→ 留在常驻，无论多长、无论超多少字符。

### 推论（现行分工）

| 内容 | 归属 | 依据 |
| --- | --- | --- |
| 8 条硬约束、授权提示 | **常驻** | T1：漏读 = 断连 / 不可逆 / 白跑 |
| 执行 SOP、看屏回退链、文档路由表、成本纪律、退出码 | `references/执行手册.md` | 漏读代价低；任务开始读一次即留在上下文 |
| API 手册 / 清单 / 细则 | `references/`，Grep 局部读 | 体积大、命中窄 |

## 三、复测（改完必跑，不跑等于没改）

```bash
cd <skill_dir> && node scripts/skill-cost.js          # 摘要；超线退出码 1
node scripts/skill-cost.js --top 6                    # 附四层最贵 TOP
node scripts/skill-cost.js --json                     # 机器可读
node scripts/skill-cost.js --save                     # 记基准，下次自动对比长了/瘦了多少
```

- 传感器同时校验：SKILL.md 提到的文件是否真的存在；其他文档里对 SKILL.md 某一节的引用（书名号写法）是否真的对得上（防搬节断链）。
- 历史落在 `scripts/.skill-cost-history.jsonl`；**每轮改动都要留一条，才能看出偏差是收敛还是反弹**。

## 四、红线

- **每轮成本（常驻层 SKILL.md）≤ 1500 tok**。
- 若新增内容属 T1（漏读即事故）而超线：**优先压缩同层其他文字的冗余**，而不是把 T1 内容赶出去。
- 备份：改动前 `cp SKILL.md` 到 `_backup/<时间戳>/`，可整目录覆盖回滚。

### 4.1 豁免项：规划层 scan-tasks **不设红线**（2026-09-17 决策）

`skill-cost.js` 里 `BUDGET.plan` 已置 `0`，规划层**只观测、不判红、不影响退出码**。
看到 `[每次规划 scan-tasks] …… 无红线（模板沉淀豁免，仅观测）` 属正常，**不要去压缩模板 description**。

理由：

1. **模板是沉淀下来的能力，建了就有用**。它不是随手攒的废话，压缩 description 等于主动降低「规划阶段靠
   description 选中正确模板」的命中率——省的是一次性的规划 token，赔的是选错/漏选后重跑一整轮任务的代价。
2. **增长有自然上限，且慢**。任务模板受真实场景数量约束，未来大概率继续增长但也增长不了几个，
   不像 references 文档那样会无界膨胀；即便未来做一次精简，也是按「合并同类模板」来做，不是按字数做。
3. **付费次数少**：规划层每次任务只付一次，不像常驻层每轮都付。

> 判据不变的部分：常驻层（每轮都付）和单篇模板/参考文档（每次任务各读一篇）的红线**照旧有效**——
> 它们才是会被反复付费、且体积能无界膨胀的地方。
