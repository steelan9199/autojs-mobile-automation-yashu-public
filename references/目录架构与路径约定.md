# 目录架构与路径约定

> 本文件从 SKILL.md 下沉而来，**按需查阅**。
> 什么时候读这里：写新脚本/新工程、路径报错、传文件落点不对、命令找不到文件时。

## 一、手机端目录架构 v3

手机端 AutoJS 脚本根目录 = `files.getSdcardPath()` + `"脚本"` 动态拼接，**全链路禁止硬编码物理路径**。

- **用户自己写的脚本**：永远留在根目录，本技能绝不触碰（技能自身也不在根目录留任何文件）；
- **`scripts-from-computer/`**：本技能从 PC 下发的一切产物的隔离区——
  - `client/` 常驻客户端本体（自更新直接落位、可手动启动；客户端启动时「自归位」到这里）；
  - `single/` 模板单脚本 + 临时探针脚本（run-task 下发落位）；
  - `project/<工程名>/` AI 项目工程（deploy-project 部署、run-project 运行、delete-project 清理）。
    注意：运行期该目录里会多出**临时入口** `__autojs-entry-<taskId>.js`（客户端把入口源码内联 + 注入
    `__TASK_ID`/`__TASK_ARGS_PATH`/`__reportProgress` 后执行；启动时清上一会话的、同工程重跑时清上一轮的）。
    它不是工程源码，别改别依赖；`engines.myEngine().source` 会显示这个名字而不是 `main.js`；
  - `data/` 配套数据（`task-args/<taskId>.json` 按单参数、`relay-config.json` 中继地址、`beep.wav` 等资源）；
  - `files/` PC 传给手机的一般文件缺省落点（pc-to-phone / send-file-to-phone 不显式指定 `--target-dir` 时）。

命名规范：本技能新建的文件夹/文件一律小写中划线（kebab-case），避免大小写歧义导致的找不到文件。

## 二、PC 端目录约定

- `<skill_dir>` = 技能根目录（SKILL.md 所在目录）；
- **用完即删**的一次性脚本 → `<skill_dir>/temp/`（判据见本节末）；
- **验证脚本与夹具**（会再跑 / 被文档按路径引用 / 承载某条硬结论的取证过程）→ `<skill_dir>/scripts/verify/<域>/`，**入库、不进 temp**：`relay/` 是 PC 侧 node 脚本（`node scripts/verify/relay/<名>`），`phone/` 是手机侧 AutoJS 脚本（须经中继下发），登记册见 `scripts/verify/README.md`；
- AI 写的 AutoJS 多文件工程 → `<skill_dir>/scripts/autojs-project/<工程名>/`（内部结构参照同目录 `autojs-min-project-template` 范本）。已预置 `project1/` 空位可直接用；`scripts/autojs代码参考例子/autojs-projects/ColorWheel` 是带 UI 界面的工程范例；
- 电脑端起 HTTP 服务、手机局域网访问的 Web 应用 → `<skill_dir>/scripts/webapp/<应用名>/`（与 `autojs-project` 的「打包推手机」语义区分：webapp 是**电脑跑服务、手机浏览器/WebView 访问**，勿混入 deploy/run 生态）。已预置 `piano/` 万能音效钢琴（`index.html` + `manifest.json` + `samples/` + `启动钢琴服务.bat`/`serve.py`）；
- **`temp/` 判据（落笔前先问一句）**：跑完即弃、且**没有任何文档按路径引用它** → 放 `temp/`；
  只要满足「以后还会再跑」「被文档引用」「是某条硬结论的证据」**任一条**，就**不许放 `temp/`**，
  按上面对应落点放正式位置。为什么较真：`temp/` 会被整目录清理（中继自动裁剪 + 人工清理），
  放进去的东西连同引用它的文档指针会一起消失——`references/实测报告/` 与 `scripts/verify/` 两个目录
  都是因为踩过这个坑才单独建出来的。

## 三、路径硬规则（本技能最高频的坑）

### 规则 1：分隔符一律正斜杠 `/`，严禁反斜杠

本机下发命令走 **Git Bash（POSIX shell）**。POSIX shell 把 `\` 当转义符，会把它悄悄吞掉，导致 `skills\autojs` 变成 `skillsautojs`、路径拼接错、`cd`/命令找不到文件。

### 规则 2：node 参数禁用 `/c/...` 形式绝对路径

把脚本绝对路径直接作为 node 参数时，`/c/Users/...` 这种 POSIX 形式会被 Windows 版 node 当成「当前盘根下的相对路径」（如解析成 `d:\c\Users\...`）而找不到文件。

**推荐做法**：脚本已用 `import.meta.url` 自定位技能根目录（实测 2026-09-16：不 `cd`、直接传带盘符绝对路径调用亦正常），所以**直接调绝对路径最稳，无需先 `cd`**：

```bash
node C:/Users/.../skills/autojs-mobile-automation-yashu/scripts/run-task.js open-app --args '{"name":"MT管理器"}'
```

用相对路径时**才**需要先 `cd` 进技能目录（`cd <skill_dir> && node scripts/run-task.js ...`）。给 node 的绝对脚本路径一律带盘符前缀（`C:/...`），禁用 `/c/...`。

### 规则 3：任务参数只写模板名，不手拼 `tasks/...`

模板名自动解析成 `tasks/<name>/<name>.js`。

### 规则 4：手机路径参数前加 `MSYS_NO_PATHCONV=1`

Git Bash 会把**以 `/` 开头的参数**（如 `--target-dir /sdcard/Download`）自动改写成 Windows 路径（实测 `/sdcard/Download` 被改成 `D:/software/Git/Git/sdcard/Download`，手机端拼出非法路径下发失败）。

```bash
MSYS_NO_PATHCONV=1 node scripts/pc-to-phone.js a.txt --target-dir /sdcard/Download
```

适用于 `--target-dir`、`delete-folder --path` 这类**手机路径参数**。

## 四、其他硬约束

- **默认端口 9421**。改动须同步：① `curl localhost:9421/health`；② `autojs-task-phone-client.js` 的 `SERVER_PORT`；③ PC 侧脚本的中继地址常量——`run-task.js` 的 `DEFAULT_BASE`、`deploy-project.js` 的 `DEFAULT_URL`（两者名字不同，别按同一个名字去找）。
- **安装依赖是前提**：`cd scripts && npm install`。
